# Warren

Id `warren` · Source: `src/lib/apps/user/warren/` · [brainstorm](../brainstorm/2026-10-21_warren.md) · [ADR-059](../adrs/059-warren.md), [ADR-045](../adrs/045-scoped-app-dependencies.md) (app-scoped packages)

## What it does

A word processor for CVs, letters and stories. A title, headings 1–3, quotes, bold, italic, underline, strikethrough, subscript, superscript, clear formatting, font size, text colour and highlight, alignment (left, centre, right, justify), links, named styles (Normal, Title, Heading 1–3, Quote) per document, tables (merged cells, header rows, borders or none, column widths), one body font per document (Inter, Burrow or a font from `/etc/fonts`), bullet, numbered and check lists, horizontal lines, an outline of the headings, word and character counts with reading time, selection counts and a word goal, smart quotes and dashes, find and replace (Mod+F), pictures (pasted, dropped, picked or taken with the camera on a phone; sized, aligned, described), page setup (A4, Letter or A5, portrait or landscape, Normal, Narrow, Wide or custom margins), headers and footers with their own formatting, pictures and page numbers, templates (CV, two-column CV, cover letter, letter, report, and the user's own in `/home/Templates`), user-placed page breaks on sheets, "Change everywhere" for a word, a list of the words used most, synonyms from on-device AI where Chrome has it, Markdown shortcuts while typing, a slash menu for blocks, focus mode and ¶ marks, a version history to preview, compare and restore, a list of misspelt words with suggestions, comments on the text, and on-device AI to rewrite or summarise a selection where Chrome has it. Saves `.warren` files; opens Word `.docx` and Markdown `.md` files as new documents, pictures included; exports `.docx` for Word, Markdown and PDF through the print dialog. Idea from LaxDOTexe.

## How it works

### Editor: Lexical, framework-agnostic

`lexical.ts`, `editor.svelte.ts`. The editor is built from Lexical Extensions: `buildEditorFromExtensions` (`@lexical/extension`) with one root extension, `@webos/warren`, that holds the namespace, theme and error handler and depends on:

| Extension | Brings |
|-----------|--------|
| `RichTextExtension` | Headings, rich-text keys (bold, italic, underline, Enter, Backspace…), paste, plus its own dependencies (Dragon, inline and triple-click normalising) |
| `HeadingAnnounceExtension`, configured `disabled` | Rich text's screen-reader heading announcements are off: opening a document would announce every heading in it |
| `ListExtension` | `ListNode`, `ListItemNode`, the list commands |
| `CheckListExtension` | `INSERT_CHECK_LIST_COMMAND`, `checked` on list items, the click and keyboard toggles |
| `HorizontalRuleExtension` (`@lexical/extension`) | `HorizontalRuleNode` (type `horizontalrule`, an `<hr>` with the theme's `wr-rule`), `INSERT_HORIZONTAL_RULE_COMMAND`, click to select it |
| `LinkExtension` | `LinkNode`, its transform and `TOGGLE_LINK_COMMAND` (Warren calls `$toggleLink` itself) |
| `TableExtension` (`@lexical/table`), configured | `TableNode`, `TableRowNode`, `TableCellNode`, `INSERT_TABLE_COMMAND`, cell selection, Tab and Shift+Tab between cells, merging; `hasHorizontalScroll` off (a table is a plain `<table>`), `hasCellBackgroundColor` off (nothing exports it) |
| `MarkExtension` (`@lexical/mark`) | `MarkNode` (type `mark`, `ids`), the comment highlight: an inline element around the commented text, theme class `wr-mark` (`wr-mark-overlap` where two meet). Excluded from copy, so a paste never duplicates a comment |
| `TitleExtension` (`title-node.ts`) | `TitleNode` (type `title`, `<p class="wr-title">`): an `ElementNode` like Quote; Enter after it gives a Normal paragraph, Backspace at its start turns it into one |
| `PageBreakExtension` (`page-break-node.ts`) | `PageBreakNode` |
| `ImageExtension` (`image-node.ts`), configured | `ImageNode`, click to select it, `DRAG_DROP_PASTE` (pasted and dropped picture files) handed to `WarrenEditor.insert_pictures`, the `selected` class on the selected picture |
| `NestedEditorExtension` (`@lexical/extension`), header and footer only | `parentEditor` is the body: selecting in one editor clears the others' selection, so there's one caret and one toolbar target |
| Markdown shortcuts (`lexical-markdown.ts:register_markdown`) | `registerMarkdownShortcuts` from `@lexical/markdown` with Warren's transformers (below), in the root extension's `register` |
| `HistoryExtension`, delay 400 ms | Undo and redo; its `canUndo` / `canRedo` signals drive the toolbar through an `effect` in the root extension's `register` |
| `InitialStateExtension`, configured | The first empty paragraph is written in a discrete update tagged `warren-load`, so a new editor isn't dirty |

The root extension's `register` also binds Tab and Shift+Tab (indent inside a list only), runs smart punctuation (below) and registers the table helpers (`lexical-table.ts:register_tables`, below). `editor.dispose()` undoes every registration. `setRootElement` on the page's `contenteditable` through an attachment, inside `untrack`: the commit runs the update listeners, which read `active`, and a tracked read would re-run the attachment (and re-mount, stealing focus) whenever another zone took focus. No React, no Svelte binding package.

`create_lexical(hooks, parent?)` builds the body, and with `parent` a header or footer: the same extensions (so anything pasted from the body has its nodes), its own history, plus `NestedEditorExtension`. Lexical sends a command a zone doesn't handle on to the body; the zones register the same handlers, so nothing falls through.

Every Lexical `$` function lives in `lexical.ts`, or `lexical-table.ts` for tables: Svelte reserves the `$` prefix in `.svelte.ts`, so `WarrenEditor` (runes) only calls plain wrappers. `WarrenEditor` owns three Lexical editors: the body (`lexical`) and `zones.header` / `zones.footer`, created up front and mounted only while switched on. `active` is the one with focus (a `focusin` on its root); the format mirror, `can_undo` / `can_redo` (one history each) and every toolbar command follow it, while Find, Change everywhere, the outline, the counts and page breaks stay on the body. A zone is "on" when its JSON is in `header_json` / `footer_json`; `set_zone(zone, false)` empties it and drops it from the snapshot. It keeps the reactive mirror the UI reads: `json` (the serialized state, replaced on every content change), the selection's `bold`, `italic`, `underline`, `align`, `block` and `size`, the selected `word`, `can_undo` / `can_redo`, and `dirty` (a revision counter against the saved one; page settings count as changes).

### Tables

`lexical-table.ts`, `table.ts` (pure), `table-resize.ts`, `warren-table.svelte`. Tables are `@lexical/table`'s nodes. Each cell holds blocks (paragraphs, headings, lists, pictures); nested tables are off.

| Piece | Where | Notes |
|-------|-------|-------|
| Insert | `warren-table.svelte` | The Table group (and its sheet) shows an 8 × 8 grid when the caret isn't in a table: hover previews the size on a mouse, a tap or click inserts it (`INSERT_TABLE_COMMAND`, no header). Cells are 40 px on a coarse pointer |
| Rows, columns, merge, split | `lexical-table.ts:table_action` | `$insertTableRowAtSelection`, `$insertTableColumnAtSelection`, `$deleteTableRowAtSelection`, `$deleteTableColumnAtSelection`, `$mergeCells` over a cell selection (drag across cells), `$unmergeCell`. Delete table puts the caret in the block after it |
| Header row | `set_table_header` | `$setTableRowIsHeader(table, 0)`: the row's cells become `th`, bold; leading header rows repeat on printed pages (`<thead>`) and in Word (`tblHeader`) |
| Borders | `set_table_borders` | A NodeState `borders` on the table (`createState`, not flat), so the JSON gets `"$": { "borders": false }` only when they're off. On screen a borderless table's cells keep a faint dashed guide; printed and in Word they have no borders and no side padding at the table's edges |
| Widths | `set_table_widths`, `table.ts` | `colWidths` are weights per grid column; `column_percents` turns them into percentages (even when missing or the wrong length). Lexical writes `<col style="width: Npx">`; a `TableNode` mutation listener (`paint`) rewrites them as percentages and sets `data-borders`. Presets (25, 33, 50, 67, 75 %, Even) set the caret's column and share the rest in proportion (`with_column_width`) |
| Resize | `table-resize.ts` | Mouse and pen: hovering within 5 px of a column border shows a handle over it (absolutely placed in the paper); dragging moves it as a guide and `move_border` trades width between the two columns; the widths are written once, on `lostpointercapture`. Touch doesn't get it, so a finger scrolling the page never grabs a border |
| Cell menu | `warren.app.svelte:table_menu` | Desktop right-click in a cell: insert above, below, left, right, merge, split, header row, borders, delete row, column or table (`dialogs.menu`). On the phone the format bar's picture button turns into a Table button while the caret is in a table, opening the same tools in a window sheet (swipe down, Done or Back to close) |
| Tab | `TableExtension` | Tab and Shift+Tab move between cells; in a list inside a cell they still indent |
| Paste | `lexical-table.ts:register_tables` | A `PASTE_COMMAND` handler (low priority): clipboard HTML holding a `<table>` (spreadsheets) is left to Lexical, which pastes it as a table or into the selected cells. Plain tab-separated text (`parse_tsv`: a tab, 2–50 columns, up to 500 rows) becomes a new table, or fills cells from the caret's one onwards, adding rows and columns as needed |
| A line after | `register_tables` | A node transform keeps a paragraph after a table that ends the document, or there's nowhere to type below it. A page break asked for inside a table goes after the table |

`blocks_of` reads a table as `{ kind: "table", borders, widths, rows: TableCell[][] }`, each cell `{ col_span, row_span, header, blocks }` (page breaks inside cells are dropped). `grid_rows` lays rows out on the grid the way Word wants: a row holds only the cells starting in it, and a cell spanning rows reappears as `continued` in the rows below. `document_text` (and so the counts and `doc count`) reads cells row by row.

### Styles

`styles.ts` (pure), `warren-styles.svelte`, `print.ts:document_css`. Six named styles: Normal, Title, Heading 1–3 (h4–h6 from a paste follow Heading 3) and Quote, each a `StyleSpec`: size (pt, 6–96), bold, italic, space before and after (pt), line height (a multiple), colour (`#rrggbb` or automatic), alignment (or none) and font (`null`, `inter` or a built-in id; Burrow is the only built-in). `DEFAULT_STYLES` reproduce what Warren looked like before: Normal 11 pt, line 1.4, 6 pt after; headings 22 / 16 / 13 pt bold with 0.8 × size before; Title 28 pt bold; Quote italic with a left rule. Paragraphs follow their style; a run's own size or colour and a block's own alignment win.

Styles inherit from Normal the way Word's are based on it: a field left automatic in Title, a heading or Quote takes Normal's, and Normal's automatic font is the document font. `document_css(scope, styles, families)` puts Normal on the scope (so lists and table text follow it) and each other style on its selector, shared by the editor (`.warren-doc`, `.zone-doc`, rebuilt when `styles` changes) and the PDF. The Styles group edits the caret's style unless another is picked; Reset puts one back. `WarrenEditor.styles` is the resolved set; a change counts as an edit. A style's built-in font is loaded once per window (`warren-{window}-{id}`) and set on the paper as `--wr-font-{id}`; the PDF embeds it as `warren-font-{id}`.

### Pictures

`image-node.ts`, `lexical.ts:insert_image`, `editor.svelte.ts:insert_pictures`, `$kit/utils/picture`. `ImageNode` is a block `DecoratorNode` (type `image`) whose four fields are flat NodeState (`createState` with `flat: true`), so the JSON is `{ "type": "image", "src", "width", "align", "alt" }` and a default value is left out:

| Field | Holds |
|-------|-------|
| `src` | A WebP data URL, at most 1600 px on the long edge, quality 0.82 (`PICTURE`, `$kit/utils/picture`, shared with Proposals). Only `data:image/png|jpeg|webp|gif` survives the model (`safe_image`); a pasted remote `<img>` is dropped, not fetched |
| `width` | Percent of the text column, 5–100 (`image_width`); a new picture gets its pixel width at 96 dpi over the column, capped at 100 |
| `align` | `left`, `center` (default) or `right` |
| `alt` | The description, for screen readers and Word |

Its DOM is `div.wr-image[data-align]` > `span.wr-image-frame` (width %) > `img` + `span.wr-image-handle`. With a fine pointer the selected picture shows the handle (bottom right, bottom left when right-aligned); dragging it sets the width live and commits on `lostpointercapture`. Touch uses the Picture group's presets (25, 50, 75, 100 %), also in the More sheet. Lexical ignores mutations inside a decorator, so the handle's DOM is safe. A click selects the picture (`NodeSelection`); Backspace and Delete remove it (rich text); the Picture group has width, alignment, description and Remove.

In: the Picture group's and the formatting bar's Insert picture menu (Take a photo on a phone through `pick_device_files({ capture })`, the device's chooser, or the OPFS picker), paste and drop (rich text's `DRAG_DROP_PASTE`). Each file is encoded, then put at the selection captured before encoding: at the very start of a block it goes before the block (Lexical's `$insertNodeToNearestRoot` would leave an empty copy of the block above), anywhere else through `$insertNodeToNearestRoot`. Once the pictures in the document pass 5 MB of data URL, a warning says saving and opening slow down (once per document opened).

### Page setup, headers and footers

`page.ts`, `sheets.ts`, `warren.app.svelte`. `geometry(page)` gives the printed width and height (landscape swaps them) and the margins: `page.margins` or the size's own (Normal: 20 mm, A5 15 mm). Presets Narrow (12.7 mm) and Wide (25.4 mm top and bottom, 50.8 mm sides) are Word's; Custom takes four numbers in mm or inches (app storage `units`), each 0–80 mm.

A header sits `zone_distance(top)` from the top edge (half the margin, at most 12.5 mm, Word's default); when it's taller than the margin leaves room for, the body starts below it after 4 mm, as Word does. The footer mirrors it. Page numbers aren't a setting of their own: the Page numbers select adds a `{page}` line to the header or footer with the chosen alignment (switching the zone on), and reads its state back from the first line that is only a page number (`is_page_number_line`: `{page}`, `Page {page}`, `{page} of {pages}`, `Page {page} / {pages}`). The Page number and Page count buttons type `{page}` and `{pages}` at the caret of the zone being edited. The tokens are plain text: the exports and the sheets fill them in.

On screen the paper is a size container, and every margin is `mm / page width × 100cqi`, so the page keeps its proportions at any window width; below a 40rem desk the side margins give way to `7cqi`. The paper holds the header zone, the body and the footer zone; a zone that's off is an empty spacer as tall as its margin. In Sheets flow each page break is a band: `--fill` (padding), a copy of the footer filled in for that sheet, the desk, a copy of the header for the next sheet. The copies are the live zone's `innerHTML` with the tokens replaced (`inert`), rebuilt when they change; Lexical doesn't police a decorator's children. So the first sheet shows the live header, the last the live footer, and the ones between show copies; numbers are sheet numbers, which differ from printed pages when a sheet runs past one page. `fill_sheets` subtracts the two zones' heights from the page height. Continuous flow shows the live header once at the top and the live footer once at the bottom, no copies.

### Templates

`templates.ts`, `templates/*.warren`, `warren-templates.svelte`. Five built-in templates are `.warren` files in the app, `import()`ed as raw text on use and read with `parse_document`, each with tuned styles: CV (one column: name, contact line, profile, experience, education, skills, references), CV (two-column: a Title name and role line over a borderless 32/68 table, contact, skills, languages and interests on the left, profile, experience, education and references on the right, 15 mm margins), Cover letter (name and contact in the header), Letter (both addresses, subject, sign-off), Report (header, `Page {page} of {pages}` footer, summary, findings, recommendations, next steps). They carry placeholders ("Your Name", "Company Name"), not lorem ipsum. File › New from template… asks to discard changes, then opens a window sheet listing Blank, the built-ins and every `.warren` in `/home/Templates` (Yours); the choice opens as an untitled document named after it, saved to `/home/Documents` by default. File › Save as template… saves the current document there through the save picker; the open file doesn't change. 

### Markdown

`lexical-markdown.ts` (Lexical side), `markdown.ts` (pure export). One transformer list serves typing and import:

| Typed or read | Becomes |
|---------------|---------|
| `# `, `## `, `### ` (deeper read as Heading 3) | Headings (Warren's `HEADING`: levels capped at 3) |
| `- `, `* `, `+ ` / `1. ` / `[] `, `[x] `, `- [ ] ` | Bullets, numbers, a checklist (stock `CHECK_LIST` first, then `UNORDERED_LIST`, `ORDERED_LIST`) |
| `> ` | Quote |
| `---`, `***`, `___` then a space or Enter | A rule (`RULE`; Smart punctuation leaves hyphens at the start of a block alone so `---` gets there) |
| `**b**`, `__b__`, `*i*`, `_i_`, `***bi***`, `~~s~~`, `[text](url)` | Bold, italic, both, strikethrough, a link (stock text transformers; no inline code, Warren has no code format) |
| Import only: `<!-- page break -->` | A page break |
| Import only: a line that is only `![alt](src)` | A picture when `src` is a `data:image/png|jpeg|webp|gif` URL (`safe_image`); otherwise a link to it (web) or the alt text, counted for a "isn't inside the file" notice |
| Import only: a GFM table | A table: the header row as header cells unless it's empty (how Warren writes a table without one), each cell's text (`<br>` = new paragraph) read with the same transformers into the cell |

**Import** (`$load_markdown`): `$convertFromMarkdownString` into the root with `shouldMergeAdjacentLines`, so wrapped lines are one paragraph (CommonMark), CRLF normalised, in one discrete update tagged `warren-load`. In the app a `.md` (or `.markdown`) opens like a `.docx`: an untitled document named after it, Save goes to Save as. `.md` is in the manifest's `tools`, not `associations`: Text Editor associates `.md`, and two associated apps would turn every double-click into an Open-with question, so Warren is offered under Open with.

**Export** (`to_markdown(editor)`) walks `blocks_of`, like the `.docx` writer, so the shell needs no editor. Blocks are a blank line apart, items of one list a line apart (a blank line between two lists keeps them apart). Runs merge while bold, italic and strike stay the same, and each stretch is wrapped `**`, `*`, `~~` with its own leading and trailing spaces outside the markers; backslashes, asterisks, underscores, tildes, backticks and square brackets are backslash-escaped, and a paragraph line that would read as a heading, list, quote, table or comment gets a backslash in front. A link is `[text](url)` (`(`, `)`, spaces percent-encoded); a line break is a hard break `\` + newline. Title is `#`, a picture `![alt](data URL)` (the file stays whole, at the cost of long lines), a page break `<!-- page break -->`, a rule `---`. Tables are GFM laid out with `grid_rows`: a spanned cell's text in its first grid cell and empty cells for the rest, blocks joined with `<br>`, pipes escaped; a table without a header row gets an empty one. Nothing else (underline, sizes, colours, alignment, styles, header, footer, sub/superscript) has Markdown and is dropped. Ways out: File › Export as Markdown…, the Export group's Markdown button, `doc export --md`.

Tested both ways in `markdown.browser.test.ts` (Markdown → Warren → Markdown gives the same text for a document using every block) and the pure writer in `markdown.test.ts`.

### Slash menu

`slash.ts` (items and `filter_slash`, pure), `lexical.ts:slash_typed` / `slash_query` / `remove_slash`, `WarrenEditor.slash`, `warren-slash.svelte`. A "/" typed (one character added just before the caret, not pasted, undone or loaded) at the start of a block or after whitespace opens it in the active zone; while the caret stays right after it in the same text node, the text between is the query (no spaces, at most 24 characters), otherwise it closes. Items: Text, Title, Heading 1–3, Bullets, Numbers, Checklist, Quote, Rule, Table…, Picture…, Page break, Template…, ranked label prefix, then a word of the label, then a keyword (`todo`, `hr`, `image`…), then a substring of three letters or more.

The editor keeps focus, so typing goes on filtering; ArrowUp/Down, Enter, Tab and Esc reach the menu as Lexical key commands at critical priority (`Hooks.on_menu_key`) and fall through when it's closed. Enter with no match closes it and types the newline. Picking removes the "/" and the query, then `WarrenEditor`'s `on_command` hands the item to the app: block styles through `set_block` (not when the block is already that list, which would take it off), rule, page break, the table sheet, the picture menu at the "/", New from template. Esc closes it and leaves the text. It also closes on blur and on switching zones.

Desktop: a `popover="manual"` (no light dismiss, no focus) anchored with `position-anchor` to a 1 px element over the "/" (placed from the character's range, re-placed on desk scroll), `position-area: bottom span-right` with flip fallbacks. Phone: an in-window bottom sheet with a Grabber and swipe to dismiss but no scrim, rows 44 px, `pointerdown` cancelled so the keyboard stays up; Back closes it.

### Focus mode

`warren.app.svelte`. The corner button in the toolbar, or Mod+Shift+F, switches it on; Esc (when nothing else took the key), the corner button that replaces the tools, or the phone's Back switch it off. Not stored. The toolbar, sidebar, format bar and status bar go. After each body update the caret's block (`current_block`: the list item, or the block in a cell or at the top) gets `wr-current`, and CSS dims every other leaf block, list item and cell block, and the header and footer, to 30 % (150 ms, so instant with Motion off). The paper gets half the desk's height as margin above and below, and the caret's line (or its block, for an empty one) is scrolled to the desk's middle, smoothly unless `motion_reduced()`. The margin isn't the desk's padding: padding counts towards the desk's minimum height and pushed it past the window.

### ¶ marks

`marks.ts`, `warren.app.svelte`. The toolbar's ¶ button or Mod+Shift+8 (app storage `marks`) adds a `.marks` layer to the paper (absolute, `pointer-events: none`, hidden in print) and `draw_marks` fills it: `·` per space, `°` per no-break space, `→` per tab (a range per character), `↵` per typed line break (a `<br>` with something after it), `¶` after each block's last character (or where an empty block starts), for the body, header and footer; decorators and the filled-in header and footer copies are skipped. Redrawn on a frame after any editor update, a paper resize or a font load. The editors' DOM and state are never touched, so saving, exports and print can't see a mark (`markdown.browser.test.ts` checks the JSON, the DOM and the Markdown are unchanged).

### Smart punctuation

`typography.ts` (pure), `lexical.ts:smart_typing`. An update listener in the root extension looks for one character typed at a caret: the caret's text node grew by exactly that character just before the caret, compared with the previous state. `smarten(text, offset)` then answers: `"` and `'` curl to “ ” ‘ ’ (opening at the start or after a space, bracket, dash or opening quote; otherwise closing, so "it's" gets an apostrophe), `--` becomes –, a third hyphen turns – into —, `...` becomes …. The replacement is a second update tagged `HISTORY_PUSH_TAG`: the history keeps the state with the straight character as its own entry, so one Undo gives back exactly what was typed. Skipped: updates tagged historic (undo and redo), history-push (Find, Change everywhere, its own replacement), paste, collaboration or `warren-load`; IME composition; text inside a link; a word before the caret that looks like a URL (`://`, `www.`, `mailto:`). Quotes are English-style whatever the language. On by default; Text › Smart quotes and dashes switches it (app storage `smart`, read on each keystroke through the getter `WarrenEditor` takes).

### Words

`words.ts`, pure. A word is `[\p{L}\p{N}]+` joined by `'`, `’` or `-`, so "don't" and "well-known" are one word each. Characters count spaces but not the line ends between blocks. Both counts come from `document_text(json)` (`model.ts`), the same walk the shell uses, so the app and `doc count` always agree.

- **Change everywhere** (`lexical.ts:change_everywhere`): `replace_all` with `WORD_MATCH`, so every text node goes through `replace_matches` (whole words, case-insensitive; an all-caps or capitalised occurrence gets the replacement in the same case), in one update tagged `HISTORY_PUSH_TAG`, so one Undo restores all of them. Selection points in changed nodes move with `map_offset`, so the selection stays on the new word. A word split across differently formatted runs ("**fa**st") isn't matched.
- **Find and replace** (`warren-find.svelte`, `lexical.ts:find_all` / `replace_match` / `replace_all`): Mod+F (a window shortcut; the browser's own find is bypassed) or Words › Find and replace opens a bar above the page. Matching is `find_matches` / `replace_matches` in `words.ts`, the same code Change everywhere runs with `WORD_MATCH` (whole words, keep case); Find uses substrings ignoring case, an optional Whole words toggle, and replaces literally. Matches are painted with the CSS Custom Highlight API (`::highlight()`, a name per bar instance), so the document isn't touched: each match's `Range` is built on the DOM text under `getElementByKey`. The current match starts at the selection (a writable `$derived` on the query and Whole words, so edits don't move it and stepping or replacing overrides it), Enter / Shift+Enter step and scroll it into view, Replace splices one match (`spliceText` without moving the selection, tagged `SKIP_DOM_SELECTION_TAG`, so focus stays in the bar) after checking the text there is still what was found, then steps past any matches inside the replacement to the next one, All is one undo step. Esc closes the bar and selects the current match; on the phone the nav bar's back closes it.
- **Stats**: reading time at 230 words a minute (`reading_minutes`, at least one minute once there's a word). With text selected, the status bar and the Words group show "N of total" words and characters, counted with the same `count` over `selection.getTextContent()`. The word goal is a number field in Words (empty is none, capped at 1,000,000); the status bar shows a bar and a percentage, green once it's reached. Setting it marks the document changed.
- **Used most** (`repeated_words`): words of four letters or more, not in an English stop-word list, used at least twice; the top eight. Clicking one selects its next occurrence after the selection, wrapping (`lexical.ts:select_next`, across runs, below); on the phone without focusing, so the keyboard stays down.
- **Synonyms**: shown only when `ai.features.prompt` isn't `no` (so never on mobile). `ai.extract` with `{ synonyms: string[] ≤ 8 }`; a chip fills the "Change to" field.

### Words across runs

`lexical.ts:$block_texts` reads each block's text across its text nodes (formatting, links and comment marks are inline elements it walks into; a line break or tab is a space), with a segment per text node mapping block offsets back to node offsets. `select_next` and `replace_word_everywhere` match on it with `find_matches` (whole words, ignoring case), so "**fa**st" is found as "fast". A replacement selects the match (anchor in the first run, focus in the last) and inserts with the first run's format and style, from the last match back so earlier offsets hold; one update tagged `HISTORY_PUSH_TAG`, so one Undo. Change everywhere and Find still match inside one run (`replace_all`, `find_all`).

### Spelling list

`spelling.ts` (pure), `spell.worker.ts`, `speller.ts` (the shared worker client), `spell-list.svelte.ts` (per window), `warren-spelling.svelte`.

- **Dictionary:** `dictionary-en` 4.0.0's `index.aff` and `index.dic` (en_US, Hunspell, from SCOWL), imported by path through the app's `node_modules` with `?url` because the package's `exports` names only its Node entry. The `.aff` is small enough to be inlined as a `data:` URL; the `.dic` is a 539 KB asset (186 KB gz). Not in the service worker's precache (`globPatterns` is js, mjs, css, html, woff2); a `CacheFirst` rule (`webos-dictionaries`, `*.aff`/`*.dic`) keeps it after the first fetch, so it works offline from then on.
- **Worker:** `nspell` runs in `spell.worker.ts`, served with `$kit/utils/worker` (`SpellApi`; `speller.ts` calls it through `spawn`). `start_speller(words)` makes one worker for every Warren window (a use count; the last `stop_speller` terminates it), which fetches and parses the dictionary and adds the personal words. Methods are `load`, `check` (the words it doesn't know), `suggest` (six at most) and `add`. Nothing loads until the Spelling group's switch is on (app storage `spelling`, so it starts with Warren after that).
- **Checking:** 400 ms after an edit, `spell_words(document_text(json))` (so a word split across runs is one word) takes `[\p{L}\p{N}]+` joined by apostrophes, splits hyphens, and skips single letters, words with digits and all-caps words (CV, PDF). Only forms the worker hasn't been asked about are sent; answers are kept for the window. `misspelt` lists the wrong ones in reading order, one row per word whatever its case, with counts.
- **Rows:** a click selects the next occurrence (`select_next`; on the phone without focusing, so the sheet stays and the keyboard stays down) and opens the row: suggestions as chips (one click changes every occurrence, keeping case, one undo step), **Ignore** (this document: `ignored_words` in the file), **Ignore all** (every document: app storage `ignored`), **Add** (app storage `dictionary` and `nspell.add`, so it can be suggested). Ignored words compare in lower case with straight apostrophes.
- **Measured** (browser test, headless Chromium on the build machine): worker ready in 53 ms, the dictionary fetched and parsed in 44 ms; this page (7,643 words, 1,645 distinct) checked in about 1 ms after the first time; the worker chunk is 11 KB (4.5 KB gz).

Chrome's own underline stays on (`spellcheck`); the list is the dictionary's view, so the two can disagree.

### Writing help

`writing-help.ts` (modes, prompt, cleanup), `warren-help.svelte`. Desktop only: the toolbar's sparkle button is there while `ai.features.prompt` isn't `no` (the same check the thesaurus uses; AiService answers `no` on the phone). With text selected (up to 6,000 characters, else a toast), it opens a menu: Shorter, Clearer, Friendlier, More formal, Summarise. ### Comments

`lexical.ts` (`add_comment_mark`, `remove_comment_mark`, `select_comment`, `comments_at`, `mark_ids_by_key`), `editor.svelte.ts`, `warren-comments.svelte`, `model.ts:mark_ids`.

- **Add:** the toolbar's comment button (desktop), or Comments › Comment on the selection (the sidebar, so the More sheet on the phone). Body only.

### Sheets

`sheets.ts`, `warren.app.svelte`. The paper is one `contenteditable`, so the sheets are drawn, not nested: in Sheets flow a page break is a band as wide as the paper (`margin-inline` minus the side margins) holding the footer, the desk and the next header (Page setup, above). CSS can't give a run of siblings a minimum height, so `fill_sheets` measures after each update and resize: each break gets `--fill` (its top padding) so the sheet before it, header and footer included, is at least one page tall, and the root gets `--tail` for the last sheet. Page height is the paper's width × height/width of the page size, so on a phone the sheet keeps the page's proportions. Sheets grow past a page; nothing is split automatically (ADR-059).

The paper is `min(page width, 100cqi − gutter)` wide with margins in proportion to it (Page setup, above), so text reflows on a narrow window instead of shrinking; the printed page uses the real size and margins. The paper takes Brand Light's tokens (scoped CSS variables), like Markdown to PDF's preview. Continuous flow drops the sheet chrome and shows a break as a labelled rule.

**PDF** (`print.ts`, `print-layout.ts`): `printable` builds a standalone page for `print_html`. A picture is a `div.picture` with the alignment around an `<img>` at its width %; the page's CSP allows `img-src data:`.

Without a header or footer the body sits in the `@page` margins. With one, Chrome (checked at 153) prints page counters only inside `@page` margin boxes, which hold one styled string, not formatted runs or a logo next to text, and `position: running()` isn't supported. So the page has `@page { margin: 0 }`, the body's margins are padding on `.doc` repeated on every page by `box-decoration-break: clone`, and each page gets its own header and footer, absolutely placed at `index × page height + distance`, with `{page}` and `{pages}` filled in. Chrome fragments columns the way it fragments printed pages; on eight random documents the count matched the printed PDF every time. A wrong count would show as a missing header on the last page or a blank extra page.

Tables print as `table.wr-table` with a `<colgroup>` of percentages, leading header rows in a `<thead>` (Chrome repeats it on each page), `colspan` / `rowspan`, `data-borders="off"` for a borderless one and `tr { break-inside: avoid }`; titles as `p.wr-title`, quotes as `<blockquote>`; run colours as inline `color` / `background-color`. Rendered through Chromium's PDF printer, the sample is two Letter pages.

### Import

`docx-import.ts`, `lexical.ts:load_html`. A `.docx` goes through mammoth (`import()`ed on the first one opened, so it isn't in the app's chunk; its chunk is named `mammoth-*`, left out of the service worker's precache and kept in the `webos-mammoth` runtime cache after the first fetch) to HTML, then `@lexical/html`'s `$generateNodesFromDOM` into a fresh editor. Style map on top of mammoth's defaults: `u => u` (mammoth ignores underline otherwise), `br[type='page'] => hr.page-break` (which `PageBreakNode.importDOM` turns into a page break), `Title` → `p.title` (a title, `TitleNode.importDOM`), `Subtitle` → h2, `Quote` and `Intense Quote` → blockquote. Inline nodes left at the top level go into paragraphs; empty paragraphs are skipped (mammoth drops empty ones itself, so an empty one is what's left around a page break or a dropped picture).

What comes across: titles, quotes, tables (with merged cells and header rows; `lift_pictures` stops at a cell, so a picture stays in its cell), headings (h4–h6 as h3), bold, italic, underline, strikethrough, subscript, superscript, Warren's ☐/☑ check glyphs (as text, not a check list), line breaks, bullet and numbered lists with nesting, links, page-break characters. What doesn't: font sizes and fonts (mammoth drops them by design), alignment, horizontal lines (an empty bordered paragraph), `w:pageBreakBefore` (so Warren's own exported page breaks), picture sizes (they come in at their pixel width), table borders and column widths, text colour and highlight, named styles, headers and footers, page setup. Pictures come through `convertImage`: each one's bytes are downscaled into a WebP data URL like a pasted picture; `lift_pictures` then moves each `<img>` out of its paragraph (a paragraph holding only a picture becomes it, keeping its alignment) before `ImageNode.importDOM` reads it. A picture the browser can't decode (EMF, WMF) is counted, mammoth's warnings (unrecognised styles) counted, and any of those shows a warning toast naming what was left out.

In the app a `.docx` opens as an untitled document named after the file (`CV.docx` → `CV.warren`), not dirty; Save goes to Save as, starting in the `.docx`'s folder, or in `/home/Documents` when that's a system folder. There's no shell import: it needs the DOM.

Shared numbers are in `page.ts`: page sizes and margins (A4 and Letter 20 mm, A5 15 mm), body 11 pt, headings, line height, paragraph spacing.

Version 6 added `id` (a UUID, the version history's folder), `comments` (`[{ id, text, quote, created, resolved? }]`, a duplicate id keeps the first), `ignored_words` (lower case, sorted, unique) and `mark` nodes (`ids`) in the body. Versions 1–4 open as they are and are saved as version 5; a Warren before 5 refuses a version 5 file.

Version 4 added `image` nodes (`src`, `width`, `align`, `alt`), `page.orientation` (only `landscape` is written; portrait is its absence), `page.margins` (mm, 0–80 each; absent is the size's Normal) and `header` / `footer`, each a Lexical editor state like `editor`, present only while switched on. Versions 1–3 open as they are and are saved as version 4; a Warren before 4 refuses a version 4 file.

Version 3 added `goal` (optional positive integer up to 1,000,000, the word goal), `horizontalrule` nodes, check lists (`listType: "check"`, `checked` on list items) and the subscript and superscript format bits. Version 1 and 2 files open as they are and are saved as version 3; a Warren from before version 3 refuses a version 3 file ("made by a newer Warren").

Version 2 added `page.font` (optional; absent or `default` is Inter, and a `default` is dropped on read) and `link` nodes (`url`, `rel`, `target`, `title`) in the editor state. `font` is checked like Settings checks it: a `builtin` id must exist, a `file` name must be a plain font file name; whether the file is still in `/etc/fonts` is found out when it loads.

`size` is `A4`, `Letter` or `A5`; `flow` is `sheets` or `continuous`. `editor` is Lexical's own `SerializedEditorState`; the envelope checks only `root` and that each node has a `type`, and Lexical's `parseEditorState` rejects anything else when the app opens it. A file from a newer format version is refused with a message. Saves go wherever the user picks (`/home/Documents` by default); the window title is the file name, unsaved changes mark the window dirty and closing asks.

Props: `{ path }` (`FILE_PROPS`); `.warren` and `.docx` are associated, so `open x.warren` and a double-click open them. No other app lists `.docx`, so Warren is its only opener; a remembered default still wins.

Shell (`commands.ts`, `shell.ts`), both reading the JSON without Lexical:

| Command | Yields |
|---------|--------|
| `doc count <path>` | A `doc-count` value: name, words, characters; open → Warren. Reads versions 1–6 (rules and pictures add nothing, table cells count their text, check items count their text; the header and footer aren't counted) |
| `doc export <path> --docx` | The `file` written beside it as `name.docx`, `name (1).docx` when taken; pictures, tables, styles, colours, header, footer, page setup and open comments included |
| `doc export <path> --md` | The body as `name.md` beside it (Markdown, above). Exactly one of `--docx` and `--md` |

Path completion is filtered to `.warren`.

## Limits

- No PDF import, no `.doc`.
- The spelling list is English (US) only; Slovenian waits on a spike (memory, licence). It knows no grammar, and Chrome's underline and the list can disagree.
- Version history keeps whole copies, pictures included, so a picture-heavy document's history grows by its size per snapshot (thinned as above). Unsaved and read-only documents get no timed snapshots. Restoring page setup, styles and the goal isn't undoable (only the text is).
- Writing help replaces with plain text: bold, links and the rest of the selection's formatting go. Desktop only, and untested against the real model (no Gemini Nano on the build machine; a stubbed `LanguageModel` stood in).
- Comments have no author or replies, are on the body only, and resolved ones don't go to Word. mammoth drops a `.docx`'s comments on import; PDF and Markdown leave them out.
- Markdown export keeps only what Markdown has: a title comes back as Heading 1, underline, colours, sizes, alignment, sub/superscript, merged cells, borders, widths, header and footer are lost; line breaks in a table cell come back as paragraphs. Pictures in Markdown are imported only when they're data URLs on a line of their own. Inline code isn't supported.
- On the phone the formatting bar's buttons stay 36 px: seven 44 px ones don't fit beside the style select at 390 px.
- A `.docx` loses fonts and font sizes, alignment, picture sizes, table borders and column widths (tables come in bordered, columns even), text colour and highlight, named styles, headers and footers, and paragraph-property page breaks on import.
- No nested tables, no cell shading or vertical alignment, no table alignment or width other than the full column. A borderless table is a layout grid, not floating text: text doesn't wrap round it.
- Column resize by drag is mouse and pen only; touch uses the width presets for the caret's column (in a merged cell, its last column).
- A style's font is the document font, Inter or a built-in; `/etc/fonts` files only as the document font. Styles have no character styles, no "based on" other than Normal, no next-style choice (Enter after any style gives Normal).
- Highlight is written as run shading (`w:shd`), which Word shows like a highlight but lists under shading.
- The .docx names the document font; Word without it substitutes one, so line breaks can differ (exporting with a font other than Inter warns about it). A font file's name stands in for its family name.
- Links in the .docx are underlined, not coloured.
- On a narrow window lines reflow differently from the printed page.
- A Lexical upgrade that changes node JSON needs a migration under the envelope's `version`.
- Change everywhere and Find see text inside one text run only ("**fa**st" isn't found as "fast"); Used most and the spelling list's jump and suggestions work across runs.
- Stop words are English, and so are smart quotes (“ ” ‘ ’ in every language).
- A horizontal line doesn't survive a .docx import; check items come back as text starting with ☐ or ☑.
- The themed spelling underline isn't checked in automation: headless Chromium has no spellchecker.
- Synonyms untested against the real model (no Gemini Nano on the build machine).
- Pictures are blocks: no text beside a picture except through a borderless table, no cropping or rotation.
- Page fields show sheet numbers on screen; a sheet that runs past a page makes them differ from the PDF's. In the live header (first sheet) and footer (last sheet) they show as `{page}` / `{pages}`, the copies between sheets show numbers and can't be clicked into.
- One header and one footer for every page: no different first page, no odd and even.
- The PDF's per-page header and footer rest on the measured page count (see Export).
- Only one picture is checked against the mammoth round trip; a real Word or LibreOffice open of the .docx (pictures, header, footer, fields) is still unverified.

# Components

The UI kit lives in `src/lib/core/components/ui/` and is imported from `$lib/core/components/ui`. Everything is built on native elements; variants come from `tailwind-variants` (`ui/variants.ts`, using `tv` from `$lib/core/utils` so it shares `cn()`'s merge rules). See every one live in the Style Guide app.

| Component | What | Notes |
|-----------|------|-------|
| `Button` | Text button | `variant`: `primary` (one per view), `secondary` (default), `quiet` (toolbars, low emphasis), `danger` (destructive only). `size`: `sm` 28px, `md` 32px, `lg` 40px; on a coarse pointer (`pointer-coarse:`) `sm` is 36px and `md` 40px, so touch targets fit a finger without a mobile flag. Fields and `Segmented` grow the same way. Icons go first, `weight="bold"`. `pressed` makes it a toggle (see below) |
| `IconButton` | Icon-only button | `label` is required: accessible name and tooltip. Defaults to `quiet`. Takes `pressed` too |
| `CopyButton` | Copy a value to the clipboard | An `IconButton` (`sm` by default) that copies `text` through the clipboard service, shows a green check and "Copied" for 1.2s, and is disabled while `text` is empty. A refused copy is an error toast from the app, so it lives inside an app window. `label` names what it copies ("Copy password") |
| `Input` | Text field | The field surface (`light-dark()`, see foundations) with a `foreground/30` ring, `leading` / `trailing` snippets for an icon or a clear button. Sizes match `Button` |
| `Textarea` | Multi-line field | The same field surface, at least 96px tall and resizable vertically; the recipe's fixed heights (touch included) are reset. `mono` for code and data: Hack, no spellcheck, autocapitalize or autocomplete. Prose stays Inter. `bind:value`, `bind:element` |
| `Select` | Native `<select>` | `appearance: base-select`, so the popup is styled and keyboard, positioning and form behaviour stay native. Layout is utility classes (no scoped `display`), so `class="hidden @lg:flex"` works on it |
| `Slider` | A value on a range: volume, a position, a brush size | A native `<input type="range">`, so keyboard, ARIA and pointer handling are the platform's. A 4px track filled with `primary` up to the value, a `foreground` thumb. `size`: `sm` 28px, `md` 32px tall (36 / 40px on touch, with a bigger thumb), so it lines up with the controls beside it. `bind:value`, or `value` + `oninput` for a seek bar |
| `Switch` | On/off that applies immediately | A `role="switch"` checkbox |
| `Checkbox` | A choice that applies on submit | `accent-primary` |
| `Segmented` | Pick one of 2–4 short options | A real radio group (shared `name`): one Tab stop, arrow keys move the choice. Takes `id` / `aria-describedby` from a `SettingRow`. `size`: `md` (default, 32px, matches `md` controls) or `sm` (28px, 36px on touch) in a toolbar next to `sm` buttons |
| `ResizeHandle` | A splitter between two panes the user sizes: Hopsprite's colour panel and filmstrip | The ARIA window-splitter pattern: a focusable `role="separator"` with `aria-valuenow`. Drag (pointer capture, previews once per frame through `onpreview`, saves on release through `oncommit`), arrow keys in 16px steps, Home goes to `min`, End to `max`, Enter, Space or double-click folds and unfolds. Dragging past half of `min` folds to `rest`. `axis` `row` or `column`; `grows_backward` (default) when the pane sits after the handle. A 1px hairline with a 12px hit area (24px on touch); `primary` on hover and drag, `cottontail` on focus. It owns no size: the caller stores it |
| `Section` | A titled group on a page | Title, description, `actions` snippet; content sits in a `rounded-xl` card with dividers, or `flush` for none. `setting` is an anchor search and links land on (see below): when targeted it gets a `primary` outline 4px outside it |
| `SettingRow` | Label, description and a control | Stacks below `@md`. Its `children` snippet receives `{ id, describedby }`; put them on the control so it gets its name and description: `{#snippet children({ id, describedby })}<Switch {id} aria-describedby={describedby} />{/snippet}`. `setting` is an anchor (see below): when targeted the row gets a `primary/10` fill and an inset 2px `primary` ring |
| `SideNav` | An app's section navigation | Sidebar at `@2xl`, tab row below. Active item is `foreground/10` with a filled primary icon. An optional `count` per item sits at the end in mono `text-2xs` (App Library's categories). Items with a `group` sit under an overline per group (sidebar and drill-in list; the tab row drops them). A `footer` snippet sits at the end of the row, or at the bottom of the sidebar. **Drill-in:** pass the page as `children` and SideNav lays out both: side by side from `@2xl`, below that the list first (44px rows with a chevron, `header` snippet on top, for search), then the page alone under a bar with a quiet "‹ `back_label`" button. `bind:open` is whether the page shows; persist it with the section. The phone's Back runs `onback` first (leave a subpage), then returns to the list (`window.on_back`, so it needs a window). Focus moves to the Back button on the way in and to the item on the way out. `list` replaces the items while set (search results). Settings, Style Guide and Activity Monitor use it |
| `Toolbar` | An app's top bar | At least 44px, `bg-background-light`, hairline below. `role="toolbar"`. Wraps onto more rows when a phone is too narrow: give the part that should stretch `flex-1` and a `min-w-*` |
| `StatusBar` | Footer metadata | 28px, mono `text-2xs` at `foreground/80`, items truncate, never wrap. No important actions |
| `Badge` | A short label or status | `tone`: neutral, primary, success, warning, error, info (tinted fill + ink) |
| `EmptyState` | Nothing to show, an error, or a first run | Icon tile, title, one line of help, optional actions. `tone="error"` for failures |
| `BoardOverlay` | A game's pause or end screen | Covers its positioned parent (the board) with `background/80` and a 2px blur, fades in, and announces itself (`aria-live`). `title`, an optional mono `detail` line (the score), actions as children with the primary one last. Takes the board's radius (`rounded-[inherit]`); pass `class` for another radius or a z-index. See [Game app](patterns.md#game-app) |
| `Spinner` | Indeterminate wait | Has a `label` for screen readers |
| `Kbd` | A key | Mono, `rounded-xs` |
| `Separator` | A hairline | `vertical` for toolbars |

**Setting anchors.** `reveal_setting(root, id)` (`ui/setting-anchor.ts`, internal to the kit, not in the barrel) finds the `Section` or `SettingRow` with that `setting` inside `root`, scrolls it to the centre (instant with reduced motion), marks it `data-targeted` for 2.4 s (the ring fades in and out over 500 ms) and, when focus was left on something hidden, focuses its first control. Settings' search and `setting` links use it; the Style Guide shows it under Surfaces.

Class recipes (`button`, `field`, `badge`) are exported too, for elements that must look like a control without being one (a link that reads as a button).

## App kit

UI only apps use lives in `src/lib/kit/components/`, imported as `$kit/components/…` (ADR-048). Core and the shell never import it. The Style Guide's App kit section shows `SwipeCompare`, `CropFrame`, `Waveform`, `AiGate` (live, in this device's state), `ai_icon` and `QrFrames`; `CodeView` and `QrCollect` (it needs a camera) aren't there.

| Component | What | Notes |
|-----------|------|-------|
| `AiGate` (`$kit/components/ai-gate`) | Wraps a whole app that needs on-device AI ([ADR-061](../adrs/061-ai-games.md)): Ask, the AI games | `features` (`prompt`, `prompt-image`) are asked once at mount; while they answer, a centered `Spinner` ("Checking for on-device AI"). Any `no`: an `EmptyState` with `icon` (default `Sparkle`), `title` (required; Ask's is "Ask isn't available on this device") and the requirements text, which is what phones always show. Otherwise the `children` snippet gets `{ availability, notice }`: `notice` is a snippet while a feature still needs its one-time download (a `background-light` strip with a `foreground/8` bottom hairline, text from `download`), `null` once ready. Render it where the app's banners go, under the toolbar. The state follows the service's `features`, so the notice goes when a download finishes in any window. `combine` (no beats download beats ready) is exported beside it |
| `ai_icon` (`$kit/components/ai-icon`) | Marks the icon of an app that needs on-device AI to work at all: Ask, Unsaid, Doodlehop, Alibi. Not apps where AI is one optional feature (Warren, Shopping List) | `icon: ai_icon(AppIcon)` in the manifest. Returns an icon component that takes the same props (`class`, `weight`, any SVG attribute) and draws the glyph plus a four-point sparkle in `primary` in the top-right corner of the same 24 box (16.5–23.5 by 0.5–7.5), so every place that draws `manifest.icon` shows it at every size with no change there. The glyph is masked 1.5 units clear around the sparkle (a real cutout, not a background fill), so it stays legible over any surface and never touches the line work. Props pass through a proxy, so a changing `weight` or `class` stays reactive |
| `CodeView` (`$kit/components/code`) | A code or data editor: API Client's body and response, Recipe Box's source | CodeMirror with the theme's tokens (`token_theme`, `token_highlight`), so it follows the palette without a rebuild. Hack at 13px, `primary` caret, `primary/28` selection. `value` + `onchange` (it doesn't bind), `label` is the editor's accessible name, `language` (loaded lazily), `read_only`, `wrap` (default on). A `rounded-md` box with a `foreground/8` hairline; give it a height (`flex-1 min-h-0`, `min-h-40`). `label` and `read_only` are read once at mount |
| `CropFrame` (`$kit/components/crop-frame`) | A crop rectangle over a picture: Image Editor's Crop tool, Shopping List's "what to read" step | Fills its positioned parent, which shows the picture at any scale. `bind:rect` in image pixels, `bounds` the image size, optional `aspect` (width / height) and `label`. A `primary` outline with rule-of-thirds lines, the outside shaded with `background-darkest/65`. Drag inside to move, eight handles to resize (`lostpointercapture` ends a drag); arrow keys move, Shift+arrows resize. Handles are small `primary` squares with a `background-darkest` ring (8px, 12px on a coarse pointer) inside larger transparent targets (24px, 44px coarse). A box under three targets a side (72px, 132px coarse; a size container query on the box) drops the mid-side handles and the thirds, and its corners sit and grab outside the box, so the subject stays visible and the inside still moves. The pure geometry (`drag_rect`, `fit_aspect`, `ASPECT_PRESETS`, `aspect_of`) is exported beside it |
| `QrFrames`, `QrCollect` (`$kit/components/qr-transfer`) | Data passed between phones as QR codes ([ADR-053](../adrs/053-qr-data-transfer.md)): Shopping List and Cards sharing | `QrFrames` takes `frames` from `encode_frames` and cycles them every 400 ms on a square up to 288px, colours flipped with the theme's scheme so modules are always dark on light; with more than one, a caption row: ‹, dots, `i / n`, ›, pause (stepping pauses). `QrCollect` is a square camera viewfinder behind a Scan with camera button, then progress dots and "3 of 5 codes"; `foreign` turns another app's frames into a message, a thrown `onpayload` shows its error and starts over. Release the camera with `visible` |
| `SwipeCompare` (`$kit/components/swipe-compare`) | Two versions of a picture under one divider: Format Lab's formats, Image Tools › Compare | A toolbar row (`controls` snippet first, the divider `Slider` while there's a `right`, then zoom out / % (Fit) / zoom in) over a checkered stage sized to `width` × `height`. `left` and `right` are snippets that get `pixelated` (true past 200%) and fill the box; `left` alone is a plain zoomable preview. `bind:split` is the divider in %. Drag anywhere at fit moves the divider; zoomed in, only the handle does and a drag pans. Pinch, Ctrl/⌘+scroll zooms, scroll pans, up to 3200%. Optional `left_label` / `right_label` chips. Instance `reset()` and `focus(rect)` (image pixels). Inside the snippets, `var(--zoom)` keeps outlines at screen size. Touch: 44px handle and controls on a coarse pointer |
| `Waveform` (`$kit/components/waveform`) | A sound to trim and cut: Soundboard's Edit audio and New pad from a video | Peaks of a `Pcm` (`$kit/utils/audio`) on a canvas in `foreground` at 70%, scaled to the loudest peak so a quiet recording still shows its shape, redrawn on resize and theme change, on a `background-darker` box (`h-24`, `rounded-lg`, `foreground/10` hairline). `bind:start` and `bind:end` (seconds) are the trim: `primary` handle bars, the outside shaded `background-darkest/65`. Drag across the middle for `bind:selection` (`Span` in seconds, `primary/22` with `primary` edges); a tap or Esc clears it. `playhead` (seconds) is a `cottontail` line. **Zoom and scroll:** a row of icon buttons on top (Zoom out, Zoom in, Zoom to selection, Fit the whole sound; 44px on a coarse pointer), then a native horizontal scroller holding a time ruler (`h-5`, mono `text-2xs` labels at `foreground/80`, ticks at `foreground/30`, spaced at least 72px on 1-2-5 steps, milliseconds when zoomed far in, `m:ss` once the sound is a minute long) over the wave. Zoom widens the content; the canvas is sticky and viewport-wide and draws only the visible seconds from a peak index built once per sound. Ctrl/⌘+wheel zooms at the cursor, a two-finger pinch at the fingers' midpoint, the buttons at the centre; from one viewport wide down to one pixel per sample. Scrolling is the browser's own (scrollbar, trackpad, swipe with momentum), so no scroll is animated by script. Handles are sliders: arrows move 1% of the visible span, Shift 10%, and the view follows the handle. A drag near either side auto-scrolls; playback turns the page when the playhead leaves the view. The selection's edges are drag targets too (16px, 44px coarse). On touch, zoomed in, a swipe on the wave scrolls and only handles and selection edges drag (at fit, a drag still selects); a tap clears the selection. Pointer capture, `lostpointercapture` ends a drag, `touch-action: none` on the handles; 28px handles, 44px on a coarse pointer. Zoom math is pure in `zoom.ts` beside it, Node-tested. The caller cuts: `cut_regions`, `subtract_regions` and `encode_wav` / `wav_blob` (PCM16) in `$kit/utils/audio`, joins with a 10 ms linear crossfade |

## Toggles

A button that stays on (a tool, a panel, a view option, a flag) is a `Button` or `IconButton` with `pressed`. It sets `aria-pressed` and the selection tint: `primary/15` fill with `primary` ink, `primary/20` on hover, whatever the variant (use `quiet`). The label stays the same when it toggles; say the action ("Statistics", "Wrap lines"). A choice of one among several (Paint's tools) is a row of pressed buttons when they're icons; with words, use `Segmented`.

## Rules

- **One primary action per view.** Everything else is secondary or quiet.
- **Labels are verbs** that say what happens: "Restore windows", "Forget all", "Check now". Not "OK" / "Submit".
- **Destructive actions** use `danger` and name the thing: "Reset", "Delete folder".
- **Icon-only buttons** only for universally understood actions (back, reload, close, zoom, upload), and always with `label`.
- **Don't nest cards.** A `Section` card holds rows, not more cards.
- **The shell uses the kit too.** Titlebar controls, toast dismiss and the start menu's pin are `IconButton`s.
- **Questions require an answer.** Show them with `dialogs.show(..., { dismissible: false })`; menus stay light-dismiss.
- **Disabled is rare.** Prefer hiding an action that can't apply, or explaining why in the description.

## Adding a component

1. It's needed by two or more apps (or the shell).
2. Build it on the native element; check whether a platform feature already does the hard part.
3. Add it to `ui/index.ts`, document it in this table, and show it in the Style Guide.

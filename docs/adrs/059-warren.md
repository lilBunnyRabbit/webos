# ADR-059: Warren
**Date:** 2026-10-21
**Status:** Implemented

## Context
LaxDOTexe asked for a free word processor for CVs, letters and stories ([brainstorm](../brainstorm/2026-10-21_warren.md)). WebOS has no rich-text editing.

## Decision
- **App `warren`**, authors LaxDOTexe and the owner. Tool sidebar with collapsible groups on the left, the page on the right; narrow containers fold the sidebar into a sticky formatting bar plus a sheet.
- **Engine: Lexical** (`lexical`, `@lexical/rich-text`, `@lexical/list`, `@lexical/history` as needed), exact versions, app-scoped dependency (ADR-045). Used through its framework-agnostic core.
- **Native file `.warren`:** `{ version: 1, page: { size: "A4" | "Letter" | "A5", flow: "sheets" | "continuous" }, editor: SerializedEditorState }`. The envelope is zod-validated; the editor state is Lexical's own JSON. File association for open.
- **Features:** headings 1-3, bold, italic, font size, bullet and numbered lists; word and character counts; "Change everywhere" for the selected word (whole word, one undo step); user page breaks (a custom node); sheets or continuous.
- **Export:** `.docx` hand-written into `write_zip` (paragraph styles, runs with bold/italic/size, numbering for lists, page breaks, `sectPr` page size); PDF through `print_html` with `@page` size and `break-before: page`.
- **Spelling:** native `spellcheck` underline only.
- **Thesaurus:** repeated descriptive words counted locally; synonyms from AiService when available, hidden otherwise.
- **Shell:** `doc count <path>` yields words and characters; `doc export <path> --docx` writes a `.docx` beside it. Both read the `.warren` JSON without mounting an editor.

## Alternatives Considered
- Own block model on `beforeinput`: no dependency, but 1.5-2.5k lines and Android IME composition risk.
- `execCommand`: no model; replace-all and export would walk Chrome's inconsistent markup.
- `.docx` or HTML as the native format: lossy round-trips.
- nspell with dictionaries for a spelling list: ~200 KB gz per language; deferred.
- Datamuse thesaurus: sends the user's words to a third party.
- Automatic fixed-size pagination: needs JS measuring; rejected for user-placed breaks.

## Consequences
- A pinned 0.x dependency to upgrade by hand.
- The .warren file holds Lexical's schema; a Lexical upgrade that changes node JSON needs a migration in the envelope's `version`.
- Other people get .docx or PDF; Warren can't open their .docx yet (added in the finalize revision).
- No list of spelling errors.

## Revision 2026-10-21: implementation
- **Packages:** `@lexical/selection` and `@lexical/utils` joined the four named above, all at exactly 0.52.0.
- **Sheets are measured.** The editor is one `contenteditable`, and CSS can't give a run of siblings a minimum height, so after each update and resize the app measures each sheet and pads the break that closes it (`--fill`) to one page. Nothing is split; sheets still grow. On a narrow window the paper reflows at the window's width (keeping the page's proportions) rather than shrinking the page.
- **Change everywhere** matches case-insensitively and keeps the case of each occurrence (all caps, capitalised); a word split across differently formatted runs isn't matched.
- **History:** Lexical can't undo the first change after its history is cleared, so loading a document seeds the history with the loaded state.
- **.docx:** a page break becomes `pageBreakBefore` on the next paragraph; the document names Inter, which Word substitutes when it's missing. Core properties (`docProps/core.xml`) are included.
- **Shell:** `doc count` yields a `doc-count` value (name, words, characters; open launches Warren); `doc export` without `--docx` fails asking for a format.

## Revision 2026-10-21: finalize
Scope from the [finalize follow-up](../brainstorm/2026-10-21_warren.md#follow-up-2026-10-21-finalize): alignment and underline, .docx import, one body font, links, find and replace.

- **Format `version: 2`:** `page.font?: FontChoice` (Settings' type: `default`, `builtin`, `file` in `/etc/fonts`) and `link` nodes. Every save writes 2; a version 1 file opens unchanged; a Warren from before refuses 2 with its "newer Warren" message. A `default` font is dropped on read, so it never sits in a file.
- **Packages:** `@lexical/html` and `@lexical/link` at exactly 0.52.0, and `mammoth` 1.13.0, app-scoped. mammoth is `import()`ed on the first `.docx` (its own ~99 KB gz chunk); `warren.app` grew from 95 to 104 KB gz; the boot chunk is unchanged.
- **.docx import:** `.docx` joined the associations (no other app lists it, so nothing is taken over; a remembered default still wins). mammoth's HTML gets a style map for underline, page-break characters (`hr.page-break`, which `PageBreakNode.importDOM` reads) and Title/Subtitle. Alignment and `w:pageBreakBefore` (what Warren's own export writes) don't come back: mammoth doesn't expose them to the HTML. The notice counts pictures, tables and mammoth's warnings.
- **Links:** `LinkNode` is registered without `registerLink` (it wants the extension signals); the toolbar calls `$toggleLink` or edits the link at the caret. Mod+K isn't bound: it's the OS launcher, and a window shortcut would win over it inside Warren. Only `http`, `https` and `mailto` reach the exports.
- **Font loading:** the font loader moved from `settings/font-loader.ts` to `core/utils/font-loader.ts` (with `fetch_faces` for built-ins) so Warren loads the same faces; each window registers its own family name. The PDF embeds the faces as `data:` URLs; the .docx names the family (a file font by its file name) and the export warns that Word substitutes it.
- **Find and replace** shares `find_matches` / `replace_matches` with Change everywhere and paints matches with the CSS Custom Highlight API; replacing from the bar skips the DOM selection so focus stays in the bar.

## Revision 2026-10-21: Lexical Extensions
From the [ultra functional follow-up](../brainstorm/2026-10-21_warren.md#follow-up-2026-10-21-ultra-functional). The editor is built with `buildEditorFromExtensions` (`@lexical/extension`, pinned at 0.52.0 in the app's `package.json`): rich text, list, link, history and a page-break extension under one root extension. The deprecated `CAN_UNDO_COMMAND` / `CAN_REDO_COMMAND` listeners are gone; the toolbar follows `HistoryExtension`'s `canUndo` / `canRedo` signals. `LinkNode` now comes with `LinkExtension` (its transform and `TOGGLE_LINK_COMMAND`). Rich text's heading announcements are configured off, so nothing a user notices changed.

## Revision 2026-10-21: wave A
Wave A of the [ultra functional follow-up](../brainstorm/2026-10-21_warren.md#follow-up-2026-10-21-ultra-functional), no new dependency:

- **Format `version: 3`:** `goal?: number` in the envelope (the word goal, per document), `horizontalrule` nodes (`HorizontalRuleExtension` from `@lexical/extension`), check lists (`CheckListExtension`, `listType: "check"`, `checked`) and the sub/superscript format bits. Versions 1 and 2 open; a Warren before 3 refuses 3. `doc count` and `doc export` read it.
- **Formatting:** strikethrough, subscript, superscript and clear formatting (character formats and font sizes; links and paragraph styles stay) in the Text group, so the More sheet too. Window shortcuts Mod+Shift+X, Mod+Shift+, , Mod+Shift+. and Mod+\. Mod+, (Google Docs' subscript) is the OS's Settings, so sub and superscript moved to Shift. Mod+\ needed `Backslash` in the shortcut key table (`shortcuts/keys.ts`).
- **.docx:** `w:strike`, `w:vertAlign`, run properties now in the schema's order (underline after size); a rule is a paragraph with a bottom border; a check item is a plain paragraph starting with ☐/☑ (List Paragraph without numbering made mammoth report an unknown style). PDF: `<hr>`, `<sub>`, `<sup>`, check boxes drawn in `document_css`, shared with the editor.
- **Outline** is a sidebar group (and so a More-sheet section), last in the list. **Stats:** reading time (230 wpm), selection counts, the goal as a bar and percentage in the status bar.
- **Smart punctuation** runs from an update listener, not a text transform: only one character typed at the caret is looked at, and the replacement is its own history entry, so Undo gives back the straight character. The toggle is in the Text group (app storage `smart`), as Warren has no settings page.
- **Spelling underline:** `::spelling-error` / `::grammar-error` in the paper's `--error` / `--info`.

## Revision 2026-10-22: wave B
Wave B (the CV wave) of the [ultra functional follow-up](../brainstorm/2026-10-21_warren.md#follow-up-2026-10-21-ultra-functional), no new dependency:

- **Format `version: 4`:** `image` nodes (`src` a WebP data URL at most 1600 px at quality 0.82, `width` as a percent of the text column, `align`, `alt`, stored as flat NodeState), `page.orientation`, `page.margins` (mm) and top-level `header` / `footer` editor states. Versions 1–3 open; a Warren before 4 refuses 4. Proposals' downscaling moved to `$kit/utils/picture` (its own `refactor:` commit) and both apps use it.
- **Headers and footers** are two more Lexical editors built from the same extensions plus `NestedEditorExtension` (vanilla, no React), so a paste from the body always has its nodes and selecting in one editor clears the others. They sit in the margins as Word places them (half the margin from the edge, at most 12.5 mm; a taller one pushes the body down). Page numbers are a `{page}` line the Page numbers select adds to the header or footer, not a separate setting, so there is one mechanism; `{page}` and `{pages}` are typed tokens filled in by the exports and the sheets. Sheets show the live header on the first sheet, the live footer on the last and filled-in copies at every break; Continuous shows each once.
- **PDF:** Chrome 153 prints page counters only in `@page` margin boxes, which hold one styled string, not runs or a logo beside text, and doesn't support `position: running()`. With a header or footer the print page has no `@page` margins: the body's padding repeats per page (`box-decoration-break: clone`) and every page gets its own absolutely placed header and footer with the numbers filled in. The page count and the zones' heights are measured first in a hidden iframe by laying the body out in page-tall columns, which Chrome fragments like printed pages (it matched the printed PDF on every document tried). Without a header or footer the page prints as before.
- **.docx:** pictures as inline `w:drawing`s with `word/media` files converted to PNG (any transparency) or JPEG, since Word before Microsoft 365 doesn't show WebP; `header1.xml` / `footer1.xml` with `PAGE` / `NUMPAGES` fields; `w:orient` and the four margins. A browser test checks the package's structure (parts, content types, relationships, element order) and a mammoth round trip; nobody has opened one in Word or LibreOffice yet, as neither is on the build machine.
- **Import:** mammoth's pictures are kept, downscaled like pasted ones; ones the browser can't decode (EMF, WMF) are reported as left out.
- **Templates:** CV, Cover letter, Letter and Report as `.warren` files bundled with the app and loaded on use, plus `.warren` files in a new `/home/Templates` (ADR-021 revision). "New from template" is a window sheet; "Save as template" uses the save picker there.
- **Not done:** a two-column CV (needs tables, wave C); different first, odd or even headers; text beside a picture.

## Revision 2026-10-22: wave C
Wave C of the [waves C–E follow-up](../brainstorm/2026-10-21_warren.md#follow-up-2026-10-22-waves-ce): tables, named styles, colour.

- **Format `version: 5`:** `table` / `tablerow` / `tablecell` nodes (Lexical's own JSON: `colSpan`, `rowSpan`, `headerState`, `colWidths`), `title` and `quote` blocks, text `style` with `color` / `background-color` as `#rrggbb`, and `styles` in the envelope (only the fields of Normal, Title, Heading 1–3 and Quote that differ from Warren's defaults; invalid fields are dropped on read). Versions 1–4 open; a Warren before 5 refuses 5.
- **Tables:** `@lexical/table` at exactly 0.52.0 (app-scoped). `TableExtension` with the scroll wrapper and cell background colours off, so a table is a plain `<table>` in the page. Borders are a NodeState `borders` on the table node (`"$": { "borders": false }`), not a subclass. `colWidths` are stored as weights (Warren writes percentages): Lexical renders them in pixels, the column on screen changes with the window and the printed one doesn't, so a mutation listener rewrites the `<col>` widths as percentages. Column resize drags a guide over the border (mouse and pen, committed on `lostpointercapture`); touch uses presets. A table ending the document always keeps a paragraph after it. A page break asked for inside a table goes after it. Plain tab-separated paste becomes a table, or fills cells from the caret's; HTML tables (spreadsheets) go through Lexical's own paste.
- **Title** is its own block (`TitleNode`, an `ElementNode` like Quote), not a heading: Word's Title has no outline level, so it stays out of the outline. Quote is rich text's `QuoteNode`.
- **Styles inherit from Normal** the way Word's are based on it: a field left automatic (font, colour, alignment) takes Normal's, in the editor's CSS, the PDF and `styles.xml` alike. A style's font is the document font, Inter or a built-in (Burrow), loaded per window like the body font and embedded in the PDF.
- **.docx:** `w:tbl` with `tblGrid` from the widths, `gridSpan`, `vMerge` (`restart` and continuation cells, laid out by `grid_rows`), borders (`nil` when off, and no side cell margins), `tblHeader` on leading header rows (header cells' runs bold), `cantSplit` on the rest; a paragraph after any table that ends a part. Styles from the document (`Title`, `Quote` with a left border and indent). Runs get `w:color` and `w:shd` (the exact colour, not `w:highlight`'s 16).
- **Import:** mammoth's tables are kept (with spans and header rows); Title becomes a title, Quote and Intense Quote a quote. Borders, widths, colours and styles don't come back (mammoth doesn't expose them).

## Revision 2026-10-22: wave D
Wave D of the [waves C–E follow-up](../brainstorm/2026-10-21_warren.md#follow-up-2026-10-22-waves-ce): Markdown, slash menu, focus mode, ¶ marks. No format bump: nothing new is stored in the document.

- **`@lexical/markdown` at exactly 0.52.0** (app-scoped) for the typing shortcuts and for `.md` import. Warren's own transformers: headings deeper than 3 become Heading 3, `---`/`***`/`___` is a rule, a whole-line `![alt](data:…)` a picture (any other address becomes a link, counted in a notice), `<!-- page break -->` a page break, and GFM tables a table (an empty header row is dropped). No inline code: Warren has no code format. Smart punctuation leaves hyphens alone at the start of a block, or `---` would become an em dash before it could become a rule. Lists imported or typed with `*` may carry Lexical's `mdListMarker` NodeState in the JSON; any version 5 Warren reads it.
- **Export is Warren's own** (`markdown.ts`, from `blocks_of`), not `$convertToMarkdownString`: it has to run in the shell without an editor like the `.docx` writer, and every non-stock piece (title, tables, pictures, page breaks, hard line breaks as `\`) would have needed a custom transformer anyway. A title is written as `#`, pictures as data URLs (the file stays whole), a table without a header row gets an empty one. Underline, sizes, colour, alignment, styles, header and footer are dropped.
- **`.md` is in `tools`, not `associations`:** Text Editor lists `.md`, so an association would have turned every `.md` double-click into an Open-with question. Warren appears under Open with; a `.md` opens as an untitled document like a `.docx`.
- **Shell:** `doc export` already took a format flag, so it gained `--md` (exactly one of `--docx`, `--md`).
- **Slash menu:** a "/" typed at a block start or after a space opens it; the editor keeps focus, so typing filters and arrows, Enter, Tab and Esc go through Lexical commands at critical priority. A `popover="manual"` anchored (CSS anchor positioning) to a 1 px element over the "/" on desktop; an in-window bottom sheet without a scrim on the phone. Table… opens the table sheet, Picture… the picture menu, Template… New from template.
- **Focus mode** (Mod+Shift+F; Esc, the corner button or Back leave it) isn't stored. The caret's block gets `wr-current` after each update; CSS dims the rest. The page gets half the desk's height as margin above and below (margin, not the desk's padding, which would raise the desk's minimum height past the window) and the caret's line is scrolled to the middle, smoothly unless motion is off.
- **¶ marks** (Mod+Shift+8, app storage `marks`): ·, °, →, ↵ and ¶ drawn into an overlay layer in the paper from range rectangles, redrawn after updates, resizes and font loads. The editors' DOM and state are never touched, so exports and print can't see them.

## Revision 2026-10-22: wave E
Wave E of the [waves C–E follow-up](../brainstorm/2026-10-21_warren.md#follow-up-2026-10-22-waves-ce): version history, a spelling list, AI writing help, comments.

- **Format `version: 6`:** `id` (a UUID naming the document's history), `comments` (`{ id, text, quote, created, resolved? }`, keyed by the ids on `mark` nodes) and `ignored_words` (lower case) in the envelope, and `@lexical/mark`'s `mark` nodes (`ids`) in the body. Versions 1–5 open; a Warren before 6 refuses 6. `doc count` and `doc export` read it; the `.docx` export writes the comments.
- **Ids:** a new document gets one when it's made; a document from before gets one on its first save; Save as (of a document that already has a file), Save as template and New from template give a new one, so a copy never shares a history. Imports (`.docx`, `.md`) are new documents.
- **Version history** in `/var/lib/apps/warren/history/<id>/`, one full `.warren` per snapshot named `{epoch ms}-{words}.warren`, so the list shows word counts without opening each. A snapshot on every save and every five minutes while a saved document has unsaved edits (checked every 30 s, skipped when the text is the same as the last snapshot); the first save over a document with an empty history also keeps the version as it was opened (at the file's modified time). Thinning after each write: everything from today, the newest of each day for 30 days, the newest of each week after (weeks from Monday). Restore puts the body, header and footer back through an ordinary update (`HISTORY_PUSH_TAG`), so Undo takes it back; page setup, styles, goal and ignored words come with it but outside Undo, comments are merged; the current state is snapshotted first. Unsaved and read-only documents get no timed snapshots. Uninstall with data removes the history with the rest of `/var/lib/apps/warren`.
- **Spelling list:** `nspell` 2.1.5 (MIT, brings `is-buffer`) and `dictionary-en` 4.0.0's Hunspell files (en_US, SCOWL size 60, MIT AND BSD), both app-scoped. The package's exports name only its Node entry, so the two files are imported by path through the app's `node_modules` with `?url`: the `.aff` (3 KB) is inlined, the `.dic` (539 KB, 186 KB gz) is an asset outside `globPatterns`, cached by a new `CacheFirst` rule (`webos-dictionaries`, `*.aff`/`*.dic`). One worker (`spell.worker.ts`) shared by every Warren window, started when the Spelling switch is first turned on (app storage `spelling`), ended when the last window stops. Words come from `document_text`, so a word split across runs is one word; the jump and the replace use a new cross-run text map (`$block_texts`), which also lets Used most select a split word. Ignore is per document (`ignored_words`), Ignore all goes to app storage `ignored`, Add to app storage `dictionary` (and `nspell.add`, so it's suggested too). A suggestion replaces every occurrence, keeping case, as one undo step. Measured in the browser test (headless Chromium on the build machine): worker ready in 53 ms with the dictionary fetched and parsed in 44 ms; this repo's `docs/apps/warren.md` (7,643 words, 1,645 distinct) checked in about 1 ms.
- **AI writing help:** a toolbar button on desktop, shown while `ai.features.prompt` isn't `no` (the thesaurus' check, the AiGate rule of hiding rather than gating), offers Shorter, Clearer, Friendlier, More formal and Summarise for the selection (up to 6,000 characters). Everything goes through `ai.prompt`, streamed into a panel under the format bar; Summarise uses the Prompt API too rather than the Summarizer, so one availability decides it. Replace, Insert below, Copy, Cancel; nothing runs on its own. Replacing writes plain text (blank lines start paragraphs): the selection's formatting isn't kept.
- **Comments:** `@lexical/mark` 0.52.0 (`MarkExtension`, in every zone so a paste fits). Lexical's mark DOM carries no ids, so a mutation listener paints each mark `data-comment="open"`, `resolved` or `none` (an id with no comment, after an undo) and `data-current` at the caret; only open ones are highlighted (`--warning` on the paper). A comment whose text is gone stays listed as detached until deleted. The `.docx` gets `word/comments.xml` and one `commentRangeStart`/`End` + `commentReference` per open comment, across runs and paragraphs (resolved ones aren't exported: Word's resolved state lives in `commentsExtended.xml`). mammoth drops comments on import; PDF and Markdown leave them out. Comments are on the body only.
- **Polish:** toolbar buttons and the focus-mode exit are 44 px on a coarse pointer; the slash menu is no longer a top-layer popover but an absolutely placed element in the window, so its `position-try-fallbacks` keep it inside the window; on the phone, the line being typed is scrolled above the slash sheet (room added under the page while it's open).
- **Not done:** Slovenian (a spike first: memory, licence), grammar, a comment thread or author, the format bar's buttons at 44 px on a phone (seven of them don't fit 390 px).

# App ports: static-utils, viewers, Tic-Tac-Toe, Profiler

**Date:** 2026-10-11
**Participants:** Owner, Claude

## Context

With `master` now the Svelte version, the next step is apps. Most of the ADR-009 catalogue can be built on the current system. Two gaps block a subset of the apps: AppDataHandle (per-app OPFS) and a close guard for unsaved changes. Neither is needed for this batch.

The owner picked this batch:
- static-utils ports
- HTML Preview and CSV Viewer, as system viewers
- the Profiler
- Tic-Tac-Toe

static-utils at its latest commit (`3acb947`, 2026-08) has these tools:

| Tool | Lines | Dependencies |
|------|-------|--------------|
| image-crop | 349 | none |
| background-remove | 343 | none (colour key on a canvas) |
| image-concat | 423 | none |
| image-split | 752 | jszip, task-manager |
| qr-reader | 516 | jsqr |
| gif-player | 1308 | gifuct-js, plus a worker |
| sprite-extract | 2795 | jszip |

The ROADMAP's "static-utils Ports" list (PDF generator, video trimmer, and others) came from older versions (v2, v3) and is out of date.

The v0 Profiler wrapped every window in `React.Profiler` and counted renders. Svelte has no equivalent, and v0's own TODO says it didn't work in production.

## Decisions

| Question | Decision | Rejected |
|----------|----------|----------|
| What the Profiler measures | **Per-window DOM activity**: a MutationObserver on each window element (mutations per second, DOM node count, peak). Also global FPS (rAF) and long animation frames (`PerformanceObserver`, `long-animation-frame`) | Global metrics only; deferring the Profiler |
| Profiler overhead | **Monitors only while the Profiler window is open.** All observers live in the app component and are disconnected on destroy. Nothing is hooked into WindowsService or the shell, so a closed Profiler has zero impact, like v0's flag-gated wrapper | An always-on collector service |
| Where tool outputs go | **Saved into OPFS.** The picker gains a save mode, `window.pick_save({ name, accept?, start_path? })`, which returns a path. Multi-file outputs (split tiles, sprite frames) pick a folder and write a new subfolder of PNGs | jszip archives; browser downloads like static-utils |
| Dependencies | **Native APIs**: `BarcodeDetector` instead of jsqr, `ImageDecoder` (WebCodecs) instead of gifuct-js. Folder output removes the need for jszip. Zero new dependencies | Porting 1:1 with jsqr, gifuct-js and jszip |
| The old stash (partial concat/crop/split ports) | Dropped; port fresh from static-utils latest | Building on the stash |

## Key takeaways

- The OS filesystem replaces downloads and zips. A tool's output is a file the user can open, move or download from File Explorer.
- The save picker in window sheets is the only OS change. The rest are apps.

# OS Back Gesture

**Date:** 2026-10-14
**Participants:** owner, Claude

## Context

Block 8's last item ([mobile shell brainstorm](2026-10-12_mobile-shell.md#back)). The phone's nav bar Back runs `back()` in `mobile-shell.svelte`: the shell overlay, then the app's `on_back`, then the window's top sheet, then home. The device's own back (Android gesture or button, iOS Safari edge swipe) is plain browser back. WebOS never pushes history, so that back leaves the site or closes the installed PWA. The only history calls are `replaceState` (router hash, VersionService). Deep links ([ADR-010 v1](2026-10-14_deep-linking.md)) only consume the hash, so they don't conflict.

The browser only reports back through `popstate`, which needs an entry above the current one.

## Topics

| Question | Decision | Rejected |
|----------|----------|----------|
| Mechanism | **One guard entry** (`pushState({ webos: "back-guard" })`, same URL). `popstate` runs the back chain and the guard is re-armed | History mirroring the layer stack (every layer pushes, drift leaves dead entries); leave it |
| At home with nothing open | **Never leaves:** always re-arm | Leave on the next back (Android style); "back again to exit" toast |
| Arming | **On the next `pointerup` or `keydown`.** Chrome skips entries pushed without user activation, so a guard pushed at boot or straight from `popstate` would be skipped. Two backs with no tap between them still leave: browser rule | Push at boot and after each pop |
| Desktop | **Same guard.** Back closes the top overlay, menu, dialog or sheet, else does nothing | Untouched on desktop; also minimising the focused window |
| Owner | First pick was both WindowsService variants. **Blocked:** `dialogs` already depends on `windows`, so windows handling sheets is a cycle. **UiService owns the guard and the chain**, gaining deps `windows`, `dialogs`. `ui.back()` is also what the nav bar calls | Windows owns the guard with a shell-registered handler (callback registry); windows ignoring sheets (nav Back and OS back would differ); each shell component |

### The chain (`ui.back()`)

1. An overlay is open: close it.
2. A system dialog or menu is on top: dismiss it if it's dismissible. A non-dismissible one (Restore) swallows back.
3. The focused window has a sheet: the same.
4. The focused window's app claims back (`on_back`).
5. Mobile: send the app home. Desktop: nothing.

Sheets now come before the app's own back. Before, the mobile shell asked the app first, so Back could navigate an app behind its own sheet.

## Key takeaways

- One back for both: nav bar Back, OS back gesture, desktop browser Back.
- WebOS can't stop a browser that skips the guard. "Never leaves" means "never leaves while the user is interacting".
- Forward after a back lands on the guard and runs back once more. Accepted.
- A pasted `#/` link fires `popstate` too. It's left to the router.

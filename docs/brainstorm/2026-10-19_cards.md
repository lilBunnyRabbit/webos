# Cards: loyalty card wallet

**Date:** 2026-10-19
**Participants:** owner, Claude

## Context

The owner uses "Moje kartice" (Android), a loyalty card wallet. Wanted: the same in WebOS, but better, with every barcode kind (QR, 1D, 2D). The repo already scans QR through the kit (`$kit/utils/qr.ts`, `qr-scan.svelte.ts`: native `BarcodeDetector`, jsQR fallback) and draws QR with `uqr`. Nothing draws 1D barcodes, PDF417, Aztec or Data Matrix.

## Decisions

- **Mobile first:** designed for the phone first (one hand, thumb reach, big targets); desktop window must still work.
- **Name:** Cards, id `cards`.
- **Drawing:** `bwip-js` as an app dependency (own `package.json`, like culori in Color Games), SVG output, per-symbology imports so only used encoders ship. Lazy with the app; boot unaffected.
- **Formats:** everything `BarcodeDetector` reads: EAN-13, EAN-8, UPC-A, UPC-E, Code 128, Code 39, Code 93, ITF, Codabar, QR, PDF417, Aztec, Data Matrix, plus "number only". Manual entry defaults: 13 digits EAN-13, letters Code 128.
- **Scanning:** extend the kit. `create_barcode_detector(formats)` + `detect_barcode()` returning `{ value, format }`; `CameraScan` reports the format. QR Reader and P2P stay QR-only. jsQR fallback reads QR only (target browser has the native detector).
- **Storage:** `/var/lib/cards/cards.json` (list) + `/var/lib/cards/photos/{id}-{front|back}.webp`. In backups via `/var/lib`; uninstall with data removes it.
- **Extras (all four):** checkout mode (full-screen code, white background, Screen Wake Lock, tap to close); scan from photo, drop and paste (paste gated on dialogs); most used first with usage count, pins, search, store colour + initial icon; front/back photos and notes.
- **Shell:** prop only. `card` prop (name or id) opens the card in checkout mode, e.g. `app launch cards card=spar`. No commands.
- **Widget:** none for now.
- **Export and import (added later the same day):** a file, `Cards.zip`, holds `cards.json` plus the photos, built with the core zip utility and saved through the save picker. Importing a file (picked or dropped) skips duplicates, meaning a card with the same number and format.
- **QR export of the list, without photos:** payload `WEBOS-CARDS:1:` + base64url(deflate-raw(compact JSON)), through `CompressionStream`; the QR is drawn with the kit's `qr_path`. Too big for one code (over 2000 characters) says so and offers the file. Add › Import from QR reads it with the camera, from a photo, or from a paste.
- **Share one card:** the card's Share shows a QR of the same payload holding that card, as a link `{origin}{base}#/app/cards?import=<payload>`, so a phone camera opens WebOS. A new `import` prop next to `card` shows a confirm sheet listing the cards before adding them.

## Implementation notes

- **Storage path:** `/var/lib/apps/cards/` (`cards.json` through `storage.file()`, photos in `photos/`), not `/var/lib/cards/`. Apps keep their data in `/var/lib/apps/{id}/` (ADR-035), and that is the folder "uninstall with its data" removes, which the decision above relies on.
- **Detector fallback:** `create_barcode_detector(formats)` asks the native detector for the asked formats it supports and falls back to jsQR only when it supports none. macOS lists no `upc_a` or `codabar` (it reads UPC-A as EAN-13), so "every format or jsQR" would have dropped every 1D format there.
- **Restored windows:** the `card` and `import` props come back with a restored window, so each window remembers the values it already handled (window storage) and a reload doesn't import or count a use twice.
- **Checkout surface:** the code sits on the theme's code surface (`light-dark(background-lightest, foreground)` with `foreground` / `background-darkest` ink), the same approach as P2P Transfer's QR. White in light themes; in Brand Dark the field is the light foreground grey, since no token is white there.

The owner asked for coupons like Moje kartice shows (Spar coupons and catalogues, "Today" badge). Findings: spar.si sends no CORS headers, and its bot protection returns 403 even to plain requests, so neither an in-browser fetch nor an on-demand scrape works without a server; Moje kartice has its own backend. Options put to the owner: a screenshot becomes a coupon (barcode, title and dates read from it, with a reminder and auto-expiry), or a serverless proxy (an exception to "No backend").

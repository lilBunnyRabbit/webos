# Docs app
**Date:** 2026-10-26
**Participants:** owner, Claude

## Context
Owner: "can we make a documentation app or maybe even its own screen (idk if needed). i would still want to keep the markdown docs - let me rephrase that i would want one source of truth - but in the app it would be a more visual repressentation of the webos documentation not just loads of text".

Today: about 2.4 MB of markdown in `docs/` (system 34 files, ADRs 75, apps 27, design 5, brainstorms 120 / 635 KB). Precedent: Settings › Roadmap (`settings/sections/roadmap.svelte`) lazy-imports `docs/ROADMAP.md?raw` and draws it. `marked` is already a per-app dependency of Text Editor (system) and Markdown PDF (ADR-045).

## Decisions
- **Home:** a system app, `docs` ("Docs"). Always there, forks too. Cost accepted: system apps are precached (ADR-065), so its page chunks (about 1.7 MB without brainstorms) join every install and every update that changes docs. Rejected: user app (a fork loses it), its own shell screen (a new shell surface for the same content), a Kernel section (ADRs, design and app pages fit poorly).
- **One source of truth:** the markdown in `docs/` is the content. Pages load through `import.meta.glob("/docs/**/*.md", { query: "?raw" })`, lazy per page. Visuals are generated from the markdown's own tables and from live registries, never written twice. Tests pin the doc shapes the parsers rely on.
- **Covers:** `docs/system`, `docs/adrs`, `docs/design`, `docs/apps`, and ROADMAP. Brainstorms stay out; a link to one opens it on GitHub.
- **Renderer:** `marked`, declared in the app's own package.json.
- **Visuals, first cut:** service graph (live kernel registry: services, dependency edges, init order; a node opens its page), ADR timeline (from the ADR index table: date, status, revisions count), app atlas (app registry joined to `docs/apps`: icon grid by category, Launch, internals page), persistence map (from `persistence.md`'s storage tables: OPFS tree and localStorage keys with their owner), plus "anything important" (design call: e.g. roadmap progress, the platform and solo swaps).
- **Layout:** sidebar + page with a table of contents, overview home (owner pick), and the map idea explored too: two home variations built (A overview cards, B zoomable map whose nodes open the reader). Pages always use the sidebar reader; on mobile the sidebar is a drawer and the contents a sheet. Owner picks after screenshots.
- **Ways in:** `docs [topic]` from the manifest's shell (completion over page ids), an "Open docs" link in each Kernel service inspector, and relative `.md` links that open in place (brainstorm and source links open GitHub).
- **Props:** `page?: string`, a page id (`services/windows`, `adrs/047`, `persistence`).

## Home pick (2026-10-26)
- **Home:** variation A (overview) stays the home.
- **Map:** variation B is kept as its own page, id `map`: a Map entry right under Home in the sidebar, a card on the overview, `docs map` and `#/solo/docs?page=map` (completion and aliases include it).
- **Switch:** the temporary A/B switch, its "Temporary" badge and the stored home variation are removed.
- **Kernel:** the read-only `Kernel.dependencies(key)` stays as built.
- **Fix:** a missing page highlights nothing in the sidebar (it highlighted Home).

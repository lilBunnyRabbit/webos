# Glimpse: throwaway photos
**Date:** 2026-11-05
**Participants:** owner, Claude

## Context
Owner: an app for temporary image storage. "I often take multiple pictures of something to have it as a 'double check', like closed doors. I want the images to be erased in x amount of time (if the time passes when closed it should be when the app gets opened). I would want an in app camera option since I often take multiple pictures quickly and opening the native app every time would take ages. I want a good gallery view for these images if I want to quickly browse through them. The camera should have flashlight and all of that."

What exists: Recorder takes photos by drawing the live preview to a canvas (`recorder/session.svelte.ts:148`) and saves to `/home/Recordings`. Color Tools (`color-tools/camera.svelte.ts`), Motion Watch and the kit QR scanner (`$kit/utils/qr-scan.svelte.ts`) each open the camera with their own code. Nothing uses the torch. No gallery exists; Media Preview shows one file. The scheduler's lazy `on_fire` (Calendar, Pomodoro) runs while any WebOS tab lives.

## Topics discussed
### Storage (decided)
App storage in OPFS: `/var/lib/apps/glimpse/`. Photos never land in `/home`.

### Expiry (decided)
Default 24 h. The time is chosen when a batch starts (before shooting) and applies to every photo of that batch. Time passing while the app is closed erases on the next open.

### Erasing (decided)
Expired photos are erased when Glimpse opens, and by a timer while its window is open. No scheduler job. Rejected: a silent scheduler job per batch with `on_fire` (it erases sooner while only WebOS is open, but adds more code and a job per batch).

### Keeping one (decided)
In the viewer, **Save to Pictures** copies the photo to `/home/Pictures`, kept for good, and **Extend** changes the batch's expiry. Rejected: extend only; fixed expiry.

### Gallery (decided)
Batches, newest first. Each row is headed with the time and a countdown ("erases in 5 h"), with the batch's thumbnails under it. A tap opens a full-screen viewer: swipe or arrow keys move through every photo, pinch or wheel zooms. Rejected: one flat grid (it loses the "this set was the door" grouping).

### Shell (decided)
Nothing. `app launch glimpse` covers it.

### Name (decided)
**Glimpse**, id `glimpse`: a quick look you don't keep. The owner left the name to Claude. It's WebOS's built-in camera.

### Camera (decided)
Owner: "explore how to do it". Research findings:
- **Frame grab vs `takePhoto()`.** Grabbing the live frame with `createImageBitmap(video)` takes under 5 ms, with no shutter lag and no stream reconfigure. `ImageCapture.takePhoto()` captures the full sensor and offers `fillLightMode`, but costs 0.3–1 s per shot on Android, and the preview can blink.
- **Controls.** `track.getCapabilities()` reports what Chrome Android has: `torch`, `zoom`, `focusMode`, `pointsOfInterest`, `exposureCompensation`. Desktop webcams mostly report none of them.
- **Orientation.** Chrome Android rotates frames to the display. A sideways shot with the screen locked to portrait needs rotating at capture time.
- **Format.** JPEG 0.85 is several times faster to encode than WebP on a phone.

Decisions:
- **Shutter: frame grab only.** Request the stream at up to 4096×3072 (`ideal`) from the back camera. Each shot runs `createImageBitmap(video)`, then goes to a worker that encodes JPEG 0.85 plus a 320 px thumbnail; the write is queued, so the shutter never waits for it. A single-shot flash is the torch switched on for the shot. Rejected: an HQ `takePhoto()` toggle (slow, device-dependent, needs a compat entry); `takePhoto()` only (bursts lag).
- **Controls**, shown only when `getCapabilities()` has them: torch, zoom (pinch and a slider), tap to focus, front/back switch and lens pick; mirrored preview on the front camera, unmirrored save; a short vibrate and a click sound as shutter feedback; a Screen Wake Lock while the camera is open; the camera released when the window is hidden.
- **Code: in the app** (`glimpse/camera.svelte.ts`). Glimpse is the only user of torch, zoom and focus. Rejected for now: a kit camera helper first. Camera-opening code exists in 4 places (`$kit/utils/qr-scan.svelte.ts` `CameraScan`, Color Tools' near-copy `Camera`, Recorder, Motion Watch). Merging them is a separate refactor.

### Batches (decided)
Opening the camera starts a batch. An expiry chip in the camera (1 h · 24 h · 3 d · 1 w, default 24 h) applies to the batch and can be changed until the camera closes. Closing ends it. The batch name is optional and set later in the gallery. Rejected: an explicit New batch step with name and expiry first (more taps before the first shot, the slowness the app exists to avoid).

### Format (decided)
`/var/lib/apps/glimpse/index.json` `{ version: 1, batches: [{ id, name?, created, expires, photos: [{ id, taken, width, height }] }] }`, `photos/{id}.jpg`, `thumbs/{id}.jpg`. Erasing deletes the files, then rewrites the index. On open, files the index doesn't list are deleted. Rejected: a folder per batch (the gallery would read N meta files).

## Key takeaways
Glimpse is a camera that forgets. Speed comes from never leaving the live stream: the shutter grabs the frame on screen, and the encode and write run off the tap.

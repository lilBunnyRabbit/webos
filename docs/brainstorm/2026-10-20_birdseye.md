# Birdseye (subject-locked video)

**Date:** 2026-10-20
**Participants:** owner, Claude

## Context

App idea from L4X: a video player where you select an object (a flying bird) and it follows it. Owner: "everything moves around the bird flying but the bird remains the stable part". So the subject stays still at the centre of the frame while the world moves around it.

A feasibility check (an investigation agent) found it possible without dependencies:
- Video Tools already has frame capture through `requestVideoFrameCallback` (`capture.ts`), a WebM encoder and muxer (`encode.ts`, `webm.ts`) and export as a task (`jobs.ts`). The kit has `crop-frame`.
- Tracking: hand-written NCC template matching, coarse-to-fine over a 2-level pyramid, searching about 3× the box, with a sub-pixel peak, slow template update and a confidence score. About 1–3 ms per frame, so 1080p keeps up.
- Gemini Nano is too slow per frame (seconds per image prompt).
- Heavier options for later: MediaPipe object detector (~5 MB, has "bird") to find the subject again after a loss; SAM2 through transformers.js (tens of MB, offline only).
- Risks: no demuxer means frame stepping is only as accurate as Chrome's playback (`mediabunny` would be a new dependency); occlusion or a crossing bird loses the track.

## Topics discussed

### Home: a new app; Video Tools modules move to the kit (decided)
Birdseye is its own app. Since a second app now needs `capture`, `encode`, `webm` and `plan`, they move to `$kit/utils/video` (ADR-048) in a separate refactor commit first.
Rejected: a "Track" tab in Video Tools.

### Edge fill: a choice, blur by default (decided)
When the locked subject nears the frame edge, the empty side is filled with a blurred, dimmed copy of the frame (default), black, or a theme colour. A zoom slider crops tighter.

### Scale: optional and smoothed (decided)
A "Follow size" toggle, off by default. The matcher tests ±5 % scales and the zoom is smoothed heavily. Rotation is never compensated (a bird has no stable angle; nauseating).

### Shell: Open with only (decided)
Registered as an "Open with" option for video files; Media Preview stays the default. No commands, since tracking needs a box drawn by hand.

### Name (decided)
Birdseye, id `birdseye`.

## Flow

1. Open a video, pause on a frame, draw a box around the subject.
2. Track (a task): play through hidden, run NCC per frame, store `track[t] = { cx, cy, scale, conf }`. Low confidence marks the frame lost; the user re-boxes there and gaps are interpolated.
3. Preview: a canvas pins the smoothed centre (forward-backward smoothing, no lag).
4. Export (a task): decode again, render each frame, encode WebM, pass the audio through.

## Feedback 2026-10-21
LaxDOTexe tried the Locked view on a 7.5 s phone clip of a swallow against blue sky, then trees. The track held about 0.3 s, then almost every frame scored lost: the bird goes from a dark silhouette to wings spread with a white belly to banking, NCC against a template learned only at ≥ 0.75 stopped matching, and the camera carried on from the last good point into the trees. Replayed on the clip: the first loss was at frame 6, and 186 of 225 frames were lost.

Decided (owner-approved, inside the app):
- **Re-acquire:** widen the search 3×, 5×, 8× per consecutive lost frame along the last velocity; match the boxed template as well as the adaptive one.
- **Blob fallback:** segment the window against its edge's background (luma and chroma), take the isolated, plausibly sized component nearest the prediction, mark the frame "found by shape" with its own timeline colour (`info`), refresh the template from confident ones, and reject busy windows (leaves) so those frames stay lost rather than wrong.
- Found while building it: a weak NCC match in a busy window was how the template drifted into the trees, so there only strong matches count and nothing is learned; and Follow size shrank the template on the flapping bird (a smaller patch scores higher), which shape frames now correct.

Result on the clip: first loss at frame 165, where the bird crosses the trees; 128 frames by NCC, 37 by shape, 60 lost, all lost frames in the trees. A synthetic shape-changing bird (`bird-fixture.ts`) is now in the tests. Details in `docs/apps/birdseye.md` and ADR-056's 2026-10-21 note.

## Key takeaways
- No dependencies for v1. The UX for fixing a lost track decides whether it's usable.

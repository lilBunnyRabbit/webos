# 1.0 release

**Date:** 2026-10-15
**Participants:** owner, Claude

## Context

0.37.0 shipped the code quality pass and held back 1.0 because the tasks service (ADR-013) and backups could still change the app API. The ROADMAP carried a draft of 1.0 criteria: fork test in CI, frozen app API, boot budget, tasks service, backups. Entry chunk today: 165 KB gz (590 KB raw). CI runs check, unit tests and build.

## Decisions

| Topic | Decision | Rejected |
|---|---|---|
| Scope | Gates + backups. Tasks stays parked and lands after 1.0 as a new, additive service | Full draft with Tasks; gates only |
| App API freeze | `docs/system/app-api.md` lists the stable surface; breaking it means 2.0. A test pins the exported names of the app-facing barrels | Doc only; `api` version field in the manifest (future proofing) |
| CI gates | Fork job (delete `src/lib/apps/user`, check, build, unit tests) and an entry chunk budget of 180 KB gz | Browser tests in CI (later); boot time on CI runners (noisy) |
| Release | `1.0.0` in package.json and changelog, git tag `v1.0.0`, GitHub Release with notes | Bump + push only |
| Backup format | One zip: `home/`, `etc/`, `var/lib/` plus `backup.json` (format version, app version, date, areas, `app.*` localStorage). Restore replaces the areas present in the zip, then reloads | Merge restore with conflict dialogs; folder mirror via File System Access |
| Backup location | On the device, never OPFS: a backup exists for when OPFS is gone. `showSaveFilePicker`, falling back to `<a download>` where the picker is missing (mobile) | `<a download>` only |
| Backup owner | New `BackupService` (`backup`) with inspector and `shell()` | Pure module in core utils + Settings |
| Backup contents | Toggle per area: Files (`/home`), Settings (`/etc`), App data (`/var/lib` + `app.*` localStorage) | Everything with no toggles; exclude `/home` |
| Shell | `backup create [--files] [--settings] [--apps]` opens the save picker; `backup restore` opens the device file picker, then a confirm. No OPFS path args | Restore from an OPFS path (restoring from the data it wipes) |
| API cleanup | Before tagging: dead types out, internal names out of the app barrel, apps import through barrels. `create_storage_handle` frozen as is | Leave all; dead code only; an `app_storage(id)` wrapper |
| Games deep paths | `$lib/core/games/time` and `games/direction` are stable import paths for kernel-free game logic (the barrel reaches the kernel) | A separate pure barrel; leave them internal |

## Key takeaways

- 1.0 is a promise about the app API and the fork, not a feature count.
- The backup lives outside the thing it protects.

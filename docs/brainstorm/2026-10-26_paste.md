# Paste as a way to open files
**Date:** 2026-10-26
**Participants:** owner, Claude

## Context
Owner: "open image and all of that for image tools and other places needs to support paste!"

Investigation: Image Tools already pastes in all 13 sections, as do about 13 other apps, each with its own copy of a `<svelte:document onpaste>` handler (18+ copies, three gate styles). Gaps:
- the file picker owns the keyboard and ignores paste, so "Open image…" then Ctrl+V does nothing;
- phones can't paste a file (long-press Paste only on text fields);
- files copied in Explorer live only in ClipboardService's memory, so Ctrl+V in an app pastes an older system-clipboard image instead;
- document-level handlers are blind in a popped-out mini window (`extract.md`);
- about 15 apps that take files have no paste (PDF Tools, Video Tools, Birdseye, Music Visualizer, Soundboard sounds, Font Viewer, Metadata, Hex Viewer, Media Preview, PDF Viewer, Nonogram from image, Settings wallpaper…).

Browser limits: `navigator.clipboard.read()` returns only the current item (images as PNG; Chrome asks permission once); a paste event can carry several files; there is no clipboard history API.

## Decisions
- **Picker Paste source:** the file picker gets a Paste button beside "This device…", and handles Ctrl+V while open. Every `pick_file` caller gets paste, phones included.
- **Clipboard view, on demand:** the Paste button opens a sheet showing what's on the clipboard now: the system clipboard item (thumbnail or text) and the files copied in WebOS, each with a thumbnail, name and type; items the caller can't accept are dimmed; pick one or several. No history (rejected: a WebOS clipboard history, a new state layer seeing only WebOS copies).
- **Ctrl+V:** one usable item pastes directly; several open the view.
- **Kit helper:** `paste_files` attachment in the kit replaces the per-app copies (standard gate, PiP-safe via the root's own document, accept filtering, WebOS files, the view when several), and is added to the apps without paste. Paint and Hopsprite stay out until "open vs insert" is decided.
- **Explorer copy:** copying files in WebOS also writes their paths as text to the system clipboard, so a paste can tell a WebOS copy from an older screenshot (ADR-025 revision). It replaces the system clipboard, as a real OS does.
- **Shell:** `clip ls`: lists the current clipboard (WebOS files, and a summary of the system item) as a value that pipes into `open`.

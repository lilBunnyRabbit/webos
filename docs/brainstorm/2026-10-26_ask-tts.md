# Ask reads answers aloud
**Date:** 2026-10-26
**Participants:** owner, Claude

## Context
LaxDOTexe: "can you include a TTS for ASK? like an automatic tts when it replies".

Ask (`src/lib/apps/user/ask/`) streams answers from Chrome's on-device model (`ask.app.svelte` appends chunks to `answer.content`; Stop aborts). Its only setting is `/var/lib/apps/ask/commands.json`, `{ version: 1, on: [] }` (`assistant.ts`). Nothing in WebOS speaks yet. The browser's `speechSynthesis` is one queue per page: `cancel()` empties all of it, voices load asynchronously and differ per OS.

## Decisions
- **Engine:** the browser's `speechSynthesis`. No dependency.
- **Owner:** a new kernel service, `speech` (SpeechService, ADR-074). It owns the page's one queue, so two windows can't silence each other by accident. Rejected: a kit helper (a module-level hidden owner, no inspector or shell), Ask calling `speechSynthesis` directly (two Ask windows cancel each other, the next app copies it).
- **Timing:** sentence by sentence while the answer streams; the tail is flushed when the stream ends. Stop and a new question stop it.
- **Sharing:** one owner speaks at a time; the newest preempts (cancel, then speak). `stop(owner)` does nothing unless that owner is speaking. Rejected: queueing behind (answers pile up).
- **Markdown:** the service strips it on request (`{ markdown: true }`): no symbols, a fenced code block becomes "Code block.". Shared by Ask and `say` on a `.md` file.
- **Closing a window** stops its speech. Speech without a window (`say`) runs to the end or until `speech stop`.
- **Voice and rate:** system-wide, in WebOS Settings › Speech, saved by SettingsService in `/etc/settings.json` as `speech: { voice: voiceURI | null, rate }`. Owner: "i guess in the settings?", then WebOS Settings over Ask's own sheet.
- **Ask:** a speaker toggle beside Send turns auto-speak on and off, saved in `commands.json` version 2 `{ version: 2, on, speak }` (v1 reads as `speak: false`). Each answer gets a Speak / Stop speaking button beside Copy, working with auto-speak off too.
- **Shell:** `say <text>` (and piped text, `cat notes.md | say`) and `speech stop`, from the service's `shell()`.

## Key takeaways
- The browser can't remove one utterance from its queue, so "stop only mine" means "only if I'm the one speaking".
